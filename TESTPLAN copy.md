## 6. Сканер + Open Food Facts

Відкривається: Add food → картка **Scan**. На симуляторі — ручний ввід коду (§0.5).

**Фази (8):** requestingPermission (поки не відповів на промпт камери — темний порожній екран із хедером, не креш, §16) → scanning (вьюфайндер, лінія) → searching (спінер + код) → found (мить, одразу форма) або handedOff (локальний хіт — мить порожнього екрана до кейпада, §16) або notFound («Create manually» + «Scan again») або offline («Retry» + «Scan again»); окремо denied («Open Settings» + «Add manually instead»). Фази перетікають fade 0.2 с; Back працює в будь-якій.

- [ ] **Типи кодів (реальний пристрій)**
      Кроки: навести на QR-код; на UPC-E (8-значний з упаковки US); на Code128 з літерами (логістична етикетка).
      Очікується: QR не розпізнається взагалі; UPC-E зчитується, але на OFF дає notFound (§16); Code128 з літерами — без креша, довгий код не ламає верстку чипа.

- [ ] **UPC-A ↔ EAN-13 локальний хіт**
      Кроки: 1) Ввести будь-який реальний 12-значний UPC-A код (з американської упаковки; або взяти 13-значний EAN, що починається з 0, і відкинути нуль) → Save. 2) Ввести той самий код із провідним нулем (13 цифр).
      Очікується: 2) без мережі, без продукту-близнюка — одразу відкривається кейпад кількості (чип коду видно тільки в префілд-формі з мережі).

- [ ] **User-Agent і два запити** (через проксі, §0.11)
      Кроки: ввести 13-значний код із провідним нулем (напр. `0` + 12-значний).
      Очікується: у запитах до openfoodfacts заголовок `User-Agent: CalorieTracker/1.0 (com.prxfitness.calorietracker; contact@utr.ua)`; запитів два — з 13 і з 12 цифрами.

- [ ] **Детект основи (g/ml) і кДж**
      Кроки: `5449000000996` (напій) і `3017620422003` (сухе). Знайти на OFF продукт лише з kJ.
      Очікується: напій → форма на ml; сухе → g. kJ-продукт → kcal порахувались (÷4.184).

- [ ] **Натрій із солі, нулі з OFF**
      Кроки: знайти продукт, у якого в OFF є salt, але нема sodium (або sodium > salt).
      Очікується: у формі Sodium = salt × 0.4 (у мг). Нутрієнти, які в OFF стоять як 0, у формі порожні («—»), не 0 (§16).

## 10. Settings

**Порядок секцій (звірити):** Premium-картка → MY GOALS → UNITS → GENERAL (Language / Reminders / iCloud) → ABOUT → рядок «Data from Open Food Facts» → Delete all data → банер → TEST (DEBUG) → футер версії.

- [ ] **Premium-картка**
      Кроки: подивитись при Преміум OFF і ON; тапнути кнопку в обох станах.

- [ ] **Goals: калорії та макро**

## 11. Нотифікації і review-промпт

**Передумова:** Reminders за дефолтом OFF, онбординг дозвіл не питає → на чистій інсталяції нічого не планується, поки не ввімкнеш Reminders. Перевіряти через Test → «Список нотифікацій» (§0.1), а не чекати реального часу.

### 11.1. Смарт-нагадування (2 на день: 14:00 і 20:00, вікно 7 днів)

- [ ] **14:00 тільки без записів**

      Очікується: на сьогодні (якщо ще не 14:00) і на всі наступні 7 днів є нотифікація 14:00.

- [ ] **20:00 залежить від прогресу**
      Кроки: (а) нічого не залогано; (б) залогати <80% цілі; (в) залогати ≥80%. Після кожного — згорнути/розгорнути → Список нотифікацій.
      Очікується: (а) 20:00 «залогай»; (б) 20:00 «лишилось X kcal»; (в) на сьогодні нотифікації 20:00 немає.

- [ ] **Логування прибирає лише 14:00**
      Кроки: залогати <80% → згорнути/розгорнути → Список.
      Очікується: 14:00 сьогодні зникла; 20:00 сьогодні лишилась з «X kcal left»; завтрашні нотифікації на місці.

- [ ] **Вікно 7 днів**
      Кроки: подивитись найдальшу дату у Списку.
      Очікується: не далі ніж 7 днів; без відкриття застосунку серія закінчується — очікувано (§16).

- [ ] **Зміна цілі без активації**
      Кроки: залогати <80% → змінити ціль калорій у Goals (не згортаючи) → Список.
      Очікується зараз: текст 20:00 зі старим числом до наступного згортання/розгортання (§17 дрібне).

- [ ] **Відкликаний дозвіл**

## 13. Пейвол і покупки

Покупки локально — StoreKit-конфіг (§0.6).

- [ ] **5 точок входу**
      Кроки: 1) закінчити онбординг; 2) Settings → Upgrade; 3) Settings → нутрієнти → ON на преміум-нутрієнті; 4) Calendar → замкнений день або «Unlock history»; 5) Used = 10 → Scan.
      Очікується: у всіх п'яти відкривається пейвол.

- [ ] **Плани і фічі**
      Очікується зверху вниз: weekly → monthly → yearly (вибраний за замовчуванням, badge BEST VALUE, ціна/міс — лише якщо стор віддав) → lifetime (caption «One-time purchase», футер «Pay once, keep forever»). Список фіч: 37 нутрієнтів / сканер / історія; iCloud у списку НЕМАЄ.

- [ ] **Ціни зі стора і кеш**
      Кроки: (а) відкрити пейвол удруге за сесію; (б) Airplane Mode → вбити застосунок → запустити → пейвол; (в) прибрати StoreKit-конфіг зі схеми → пейвол; (г) повільна мережа → запуск → одразу пейвол.
      Очікується: (а) ціни миттєво, без блимання; (б) скелетони; (в) «—»; (г) скелетони, які добігають до цін.

- [ ] **Кеш живе весь процес**
      Кроки: змінити ціну в `.storekit` → відкрити пейвол без перезапуску → перезапустити → пейвол.
      Очікується: до перезапуску стара ціна, після — нова, без сміття.

- [ ] **Закриття**
      Кроки: (а) пейвол після онбордингу → свайп-даун → чекати X; (б) пейвол із Settings → свайп-даун.
      Очікується: (а) свайп не закриває, X через 1.5 с; (б) закривається свайпом одразу.

- [ ] **Купівля**
      Кроки: Continue → підтвердити в системному шиті. Окремо: Continue → Cancel у шиті. Окремо: Manage Transactions → зробити помилку (напр. вимкнути мережу) → Continue. Окремо: швидко двічі тапнути Continue.
      Очікується: спінер → пейвол закрився → преміум активний, переживає перезапуск; Cancel → тихо лишились на пейволі; помилка → алерт «Purchase failed»; подвійний тап ігнорується.

- [ ] **Restore**
      Кроки: (а) з активною підпискою → Restore; (б) без покупок → Restore; (в) преміум активний, підписка вже expired у Manage Transactions → Restore; (г) офлайн → Restore.
      Очікується: (а) пейвол закрився; (б) нічого — нуль фідбеку (§17); (в) преміум знято, пейвол лишився відкритим мовчки (§17); (г) алерт із заголовком «Purchase failed» (копірайт — §17).

- [ ] **Після покупки все відкрилось**
      Кроки: купити → пройти Calendar, нутрієнти, сканер, банерні місця, Settings-картку.
      Очікується: замки зникли (живо), 37 нутрієнтів вмикаються, сканер без ліміту й реклами, банерів немає, картка «Premium active».

- [ ] **РЕГРЕСІЯ: ресинк на активації** (фікс 2026-08-04)
      Кроки: купити → Manage Transactions → Expire/Refund → згорнути і розгорнути застосунок.
      Очікується: преміум злетів без ручного Restore; замки й банери повернулись.

- [ ] **Офлайн не знімає преміум**
      Кроки: купити → Airplane Mode → вбити → холодний старт.
      Очікується: преміум на місці (кеш RevenueCat), isPremium не блимає.

- [ ] **Переінсталяція**
      Кроки: купити → видалити застосунок → встановити → пейвол → Restore.
      Очікується: преміум повернувся.

## 14. Локалізація, RTL, доступність, дані

### 14.1. Мови (Settings → Language)

Смоук-вибірка: en → uk (кома, плюрали) → ar (RTL + арабські цифри) → he (RTL, латинські цифри) → de/fr (довгі рядки) → el/fi (найбільша експансія) → zh-Hans (не порожньо).

- [ ] **Ризикові місця на обрізання**
      Кроки: для кожної мови з дужок подивитись: сегмент Units «US · oz, fl oz» (ar/ur/bn/ru, особливо на SE) · таб Settings (de «Einstellungen») · «Avg carbs» у календарі (fi) · «Carbs» (sl/hr) · кнопки пейвола (fr/pt-PT) · алерт «Notifications are off» (de/fi/el).
      Очікується: текст не обрізаний і не наїжджає.

- [ ] **Плюрали**
      Кроки: uk/ru/pl → 1, 2, 5, 11, 21 записів → підпис «N items · X kcal»; «%lld added» у формі; «%lld tracked»; «about %lld weeks» в онбордингу.
      Очікується: «N items» правильними формами; решта — плоскі форми, оцінити прийнятність.

- [ ] **Що міняється одразу, а що після рестарту**
      Кроки: перемкнути мову → пройти Today, Add food, кейпад, календар.
      Очікується: усі тексти одразу; роздільник чисел (вкл. клавішу кейпада), «Wednesday, 8 July», літери днів — тільки після рестарту (очікувано). Пошукати «змішані» рядки (частина старою мовою).

- [ ] **Мова нотифікацій і дозволів**
      Кроки: Reminders ON → перемкнути мову → Список нотифікацій. Потім рестарт → чиста інсталяція → камера/ATT.
      Очікується: після перемикання серії переплановані новою мовою (заплановані ДО зміни — старою, §17); тексти системних дозволів — мовою застосунку.

- [ ] **uk-алерт нотифікацій**
      Очікується зараз: «Відкрити Параметри» і «в Налаштуваннях» в одному алерті — узгодити (§17).

### 14.2. RTL (ar / he / ur)

- [ ] **Жести**
      Кроки: свайп календаря; swipe-to-delete в щоденнику.
      Очікується: дзеркальні; Delete з'являється на зовнішньому (лівому) краї.

- [ ] **Іконки і фон**
      Очікується: шеврони/стрілки дзеркалені; прогрес-бари ростуть справа наліво; аврора-фон дзеркалиться; вьюфайндер сканера НЕ дзеркалиться (навмисно).

- [ ] **Кейпад**
      Кроки: ввести «١٥٠٫٥».
      Очікується: 150.5; клавіша роздільника «٫»; ASCII-цифри на клавішах поруч з арабськими цифрами значення виглядають узгоджено.

- [ ] **Онбординг ar**
      Кроки: `-resetOnboarding 1` + мова ar → пройти.
      Очікується: колесо зросту в імперії — ASCII «5′10″», колесо ваги — арабські цифри (узгодженість вирішити); прогрес-капсула росте справа; переходи кроків дзеркальні.

- [ ] **Екрани без RTL-прев'ю**
      Кроки: пройти руками Onboarding, Scanner, NewProductForm, Settings, Goals.
      Очікується: нічого не «злипло» і не вилізло.

### 14.3. Формати

- [ ] Кроки: uk і en → залогати 1234.5 г; Units US → продукт 1000 ml.
      Очікується: uk «1 234,5», en «1,234.5»; максимум 1 знак після коми; цілі без «.0»; 1000 ml = «33,8 fl oz»; «per 3.5 oz» не змінює kcal поруч.

### 14.4. Розміри / доступність

- [ ] **Dark mode**
      Кроки: увімкнути темну тему пристрою → пройти всі екрани, шити, алерти, клавіатуру, Safari-шит.
      Очікується: застосунок повністю світлий (форс light), включно з системними елементами.

- [ ] **Dynamic Type**
      Кроки: Settings → Accessibility → Display & Text Size → Larger Text → максимум (AX5) → пройти Today (кільце калорій), макро-підписи, рядки щоденника, сітку календаря, кейпад, сегменти, нижній бар сканера.
      Очікується: нічого не обрізано, кільце стискається, кнопки сканера лишаються 54/50 pt. Найгірші комбо: ar + AX3 + iPhone SE, de + AX3 + SE.

- [ ] **Пристрої**
      Кроки: iPhone SE / 16 / 16 Pro Max → прокрутити кожен список до кінця.
      Очікується: останню картку не перекриває FAB/таб-бар.

- [ ] **VoiceOver**
      Кроки: увімкнути VoiceOver → пройти комірки календаря, кільця, рядки щоденника, Back сканера.
      Очікується: комірки озвучують стан («…locked. Upgrade…»); свайп-видалення недоступний, але контекст-меню Edit/Delete доступне; Back сканера озвучується як «Cancel» (§17 дрібне).

### 14.5. Дані / iCloud (2 пристрої з одним Apple ID)

- [ ] **Синк працює**
      Кроки: iCloud ON на обох → рестарт → залогати на A → почекати → подивитись на B. Потім OFF → рестарт.
      Очікується: з'явилось на B; після OFF локальні дані на місці, без крешів.

- [ ] **Без iCloud-акаунта**
      Кроки: вийти з iCloud на пристрої → тумблер ON → рестарт.
      Очікується: працює локально без крешів. ⚠️ UI бреше: тумблер ON, футноута немає, синку немає (§17).

- [ ] **Мерж налаштувань**
      Кроки: старий пристрій A з налаштуваннями → чиста інсталяція на B з iCloud → дочекатись синку. Окремо: тримати Settings відкритим на B під час мержу.
      Очікується: один UserSettings, налаштування A не перетерті; записи не дублюються; на екрані Settings значення можуть стрибнути — без крешів.

- [ ] **Barcode-близнюки**
      Кроки: на A зберегти продукт за 12-значним кодом, на B — той самий за 13-значним з нулем → синк. Окремо: той самий код в однаковій формі на обох.
      Очікується: різні форми НЕ склеюються (нема нормалізації в дедупі — §17); однакова форма → один продукт.

- [ ] **Оновлення поверх**
      Кроки: поставити новий білд поверх старого (не видаляючи).
      Очікується: дані на місці, без крешу.

- [ ] **Продуктивність**
      Кроки: iCloud ON + Тестові дані → 10 разів згорнути/розгорнути.
      Очікується: без помітного лагу.

## 17. Кандидати в баги (аудити 2026-08-03/04): перевірити/вирішити

**Середні:**

- DEBUG Premium override злітає при кожній активації сцени (syncEntitlement перезаписує isPremium) — методика перевірки гейтів ненадійна (§0.2, §15).
- Північ знищує відкритий флоу Add food/кейпада/редагування на Today (`.id(dayKey)` міняє identity) — введене губиться без попередження.
- Гонка в сканері: Back рівно в момент приходу OFF-відповіді → реклама може з'явитися поверх Add food + мовчазна втрата скану (вузьке вікно, фікс 08-04 його не закриває).
- CloudKit: близнюки продукту під 12- і 13-значною формою коду переживають dedupeMerged (нормалізації штрихкоду в дедупі немає) — суперечить інваріанту «один barcode = один продукт».
- iCloud: мовчазний фолбек на локальний стор → тумблер ON бреше (синку немає, індикації немає).
- Reminders ON + відкликаний у iOS дозвіл → тиша без жодної індикації; тумблер синкається через CloudKit, а дозвіл — per-device (на другому пристрої ON без дозволу = нічого не приходить).
- Перша відмова в дозволі нотифікацій (notDetermined → Don't Allow) → тумблер досі мовчки відскакує без алерта (алерт лише з другого тапа).
- Restore без покупок — нуль фідбеку; Restore, що знімає преміум, лишає пейвол відкритим мовчки; помилка Restore показує алерт «Purchase failed».
- Сканер лишається в denied після видачі дозволу в iOS Settings (до перевідкриття).
- Calendar: Month → Week → Month може з'їхати на попередній місяць (anchor drift); Month → Week відкриває тиждень 1-го числа, а не поточний.
- Review-тригер «згорає» без показу, якщо застосунок згорнути протягом ~1 с після активації (consume раніше за showRequest).
- Показ кількості >9999 в одиниці показу обрізається до 4 цифр (база права, екран і жива картка брешуть).
- Edit product: активне поле «Per» мовчки перемасштабує всі значення при Save; форма продукту «на X» показує округлені до 0.1 значення і Save без правок перезаписує ними точні (дзеркало виправленого бага кейпада).

**Дрібні:**

- CTA «Add to today» при логуванні в минулий день (текст).
- Порожній стан пушнутого «сьогодні»: текст «Торкніться "+"» без FAB + повний макет з банером і нульовою карткою суми.
- Число залишку червоне вже при >100%, кільце amber лише >105% (узгодити з правилом «без червоного»).
- Подвійна хептика: на клавішах кейпада і на успішному лозі (дві success).
- Language → System не показує футноут рестарту; сам шит пікера мов показує футер «Restart…» завжди (навіть без потреби).
- «Manages via App Store» у Premium-картці — кострубатий копірайт (уже в 35 локалях); uk-алерт нотифікацій змішує «Параметри» і «Налаштування».
- GoalsCalculatorSheet жорстко cm/kg при US units.
- Немає індикації залишку безкоштовних сканів (ліміт з'являється раптово пейволом); `PremiumGate.remainingFreeScans` — мертвий код із застарілим коментом «still counts down».
- ATT-алерт поверх онбордингу.
- Resume онбордингу перераховує план з дефолтів (введені відповіді губляться); Skip на кроці «Your plan» стирає відредагований план.
- Кілька свайп-рядків можуть бути відкриті одночасно; після Cancel рядок лишається відкритим.
- Delete all data скидає unitSystem на дефолт пристрою (не на вибір юзера), повертає 10 сканів (лупхол) і примусово ставить onboardingCompleted=true.
- Пошук з одного пробілу ховає Recents, але показує повний список.
- Зміна цілі калорій не перепланує вечірню нотифікацію до наступної активації; мова вже запланованих нотифікацій — стара до рестарту.
- Мікронутрієнт з явним «0» рахується у «N added», але не зберігається.
- Хінт календаря «Tap a day with a ring…», хоча тап працює і по дню без даних.
- VoiceOver: Back сканера озвучується як «Cancel».
- Застарілі коменти в коді: «3 free scans» і «Local premium override…» (UserSettings), «premium is active» (CalorieTrackerApp), «still counts down» (PremiumGate), «stat-card taps drive it» (CalendarTabView) vs «Cards are read-only» (CalendarStatsRow).
