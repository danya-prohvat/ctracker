# Реліз-тестплан — Calorie Tracker

Ручний чекліст для прогону перед кожним релізом. Тестового таргета в проєкті немає — усе покриття ручне.

- **Повний прогін**: ~2–3 год (усі секції).
- **Швидкий смоук**: секція 1 (~20 хв) — мінімум перед будь-яким сабмітом.
- Секція 16 — одноразові конфігураційні перевірки перед релізом (блокери).
- Секція 17 — «відомі особливості»: очікувана поведінка, яку не треба репортити як баги.
- Секція 18 — кандидати в баги, знайдені аудитом коду 2026-08-03: перевірити/вирішити.

---

## 0. Підготовка

**DEBUG launch-аргументи** (Scheme → Arguments):
`-seedSample 1` (90 днів історії: дірки + всі стани кілець), `-skipOnboarding 1`, `-resetOnboarding 1`, `-initialTab calendar|settings`, `-openGoals 1`, `-showAddSheet 1`, `-initialAddRoute new|scan|qty`.

**Settings → Test** (тільки DEBUG-білд): Premium override · Seed sample data · Reset free scans («Used: N») · Ads: skip/restart ad-free day · Reset onboarding · Scheduled notifications · Test re-engagement (minutes) · Review: advance day / reset triggers.

**Скидання станів**: ATT і дозвіл камери — переінсталяція (або `xcrun simctl privacy … reset`); grace-period реклами — кнопки Ads у Test; сканів — Reset free scans; оцінки — Review: reset triggers.

**Покупки**: `.storekit`-конфіг підключений до схеми (Debug). Але RC SDK підключений → ціни тягнуться з бекенду RevenueCat (потрібен налаштований offering + мережа); без офферінгу плани показують «—», а покупка дає алерт. Для перевірки самих гейтів — Premium override; для реального білінгу — Sandbox/TestFlight.

## 1. Швидкий смоук (~20 хв)

- [ ] Чиста інсталяція → онбординг проходиться до кінця → пейвол після ~1 с → X (з'являється через 1.5 с) закриває.
- [ ] ATT-промпт з'явився один раз; відмова нічого не ламає.
- [ ] Today: створити продукт → залогати → рядок з'явився, кільця анімувалися, числа «перекрутилися».
- [ ] Редагувати кількість запису → суми оновилися. Видалити запис → підтвердження → зник.
- [ ] Сканер (симулятор: ручний ввід коду): скан реального штрихкоду → префіл-форма → зберегти → продукт у списку.
- [ ] Calendar: сітка малюється, тап по дню з кільцем → день-детейл; дні старші 30 днів — замки, тап → пейвол.
- [ ] Settings: цілі редагуються, Units перемикаються, мова перемикається (UI одразу), Delete all data працює.
- [ ] Premium override ON → замки/реклама зникли, всі нутрієнти вмикаються. OFF → повернулося.
- [ ] Перемкнути мову на ar → RTL-розкладка, свайпи дзеркальні, цифри не ламаються.
- [ ] Білд без RevenueCat SDK збирається (умовна компіляція жива).

## 2. Перший запуск і онбординг

**Сідування за регіоном пристрою:**
- [ ] Регіон US → Units = US (oz/fl oz); UK/UA/DE/FR/JP → Metric. Повторні запуски вибір юзера не перезаписують.
- [ ] Мова = мова пристрою, рядок Language = «System» без футноута.
- [ ] Перші 24 год після інсталу — жодної реклами ніде (grace period).

**Кроки (7):** стать (авто-перехід 0.2 с; є «Prefer not to say») → вік (wheel 10–99, дефолт 25) → зріст/вага (тумблер юнітів; метрика 120–220 см / 35–200 кг, імперія 4′0″–7′0″ / 77–440 lbs) → активність (4 картки, авто-перехід) → цільова вага (підпис «about N weeks», темп 0.5 кг/тиж) → «Calculating…» 1.8 с → «Your plan» (редактор плану) → Continue.

- [ ] Прогрес-капсула росте, Skip є на кожному кроці.
- [ ] Тумблер юнітів пише в Settings **одразу**: перемкнути на ft·lbs → Skip → Settings → Units = US.
- [ ] Skip: цілі лишаються дефолтними (2000/150/67/200). Finish: цілі з редактора плану записані.
- [ ] На US-локалі онбординг стартує в імперії.
- [ ] Після finish/skip: ~1 с на Today → пейвол у fullScreenCover (єдиний вихід — X через 1.5 с, свайпа немає).
- [ ] ATT-алерт прилітає на першій активації (~0.7 с) — може лягти поверх онбордингу; переконатися, що флоу не ламається.
- [ ] Перерваний онбординг (вбити застосунок на кроці 4–6) → відновлюється на тому кроці; план при цьому перераховується з дефолтів (відома особливість, див. §18).

## 3. Today і щоденник

**Вигляд:**
- [ ] Великий заголовок «Today» злипається в inline при скролі; підзаголовок з датою — тільки iOS 26+.
- [ ] Кільце калорій 132 pt + «залишилось сьогодні»; три макро-кільця з «з 150 g»; FAB «+» з градієнтом; таб-бар видимий.
- [ ] Кільця заповнюються пружинкою при появі; числа — `.numericText`-анімація.
- [ ] Тап по зоні макро-кілець → рядок «P X% · F Y% · C Z%»; на порожньому дні не з'являється.
- [ ] Net carbs (якщо ввімкнено в Goals): рядок «Net carbs: X»; продукт без даних клітковини → «—», не «0»; клітковина > вуглеводів → 0, не мінус.

**Кольори (ніколи не червоні кільця):**
- [ ] < 105% цілі → дуга акцентна (калорії зелена, P/F/C у своїх кольорах), трек = той самий колір 18%.
- [ ] > 105% → дуга І трек amber; дуга обрізана на 100% (без другого витка). Кожне макро-кільце має свій незалежний поріг.
- [ ] 100–105%: число залишку вже червоне, кільце ще зелене (задокументована розбіжність — §18).
- [ ] Комірка календаря того ж дня узгоджена: <80% сіра, 80–105% зелена, >105% amber.

**Вітаміни й мінерали:**
- [ ] Розкриття/згортання easeInOut, шеврон 180°; «Tracked: N».
- [ ] Goal-нутрієнт ≥100% → зелений чекмарк; limit-нутрієнт (sodium, sugar, satFat, transFat, cholesterol, caffeine): 90–100% amber-смужка, >100% червона + текст «+X over» (чекмарка НЕМАЄ).
- [ ] Немає даних → «—» без смужки; порожній день → реальні «0 / ціль» зі смужкою 3 pt. Долити продукт з даними → «—» стає сумою.
- [ ] Trans fat (без дефолтної норми) → тільки значення, без «/ ціль» і смужки.

**Записи:**
- [ ] Свайп рядка → Delete 88 pt; тап по відкритому рядку закриває його (не відкриває редактор); лонг-тап → меню Edit/Delete.
- [ ] Будь-яке видалення — тільки через підтвердження («…Цю дію не можна скасувати», назва = знімок із запису). Cancel → рядок лишається відкритим.
- [ ] Вставка/видалення рядків анімовані; видалення останнього → плавний свап на зелений порожній стан, «0 items · 0 kcal».
- [ ] Стрес: швидко видалити 3–4 рядки; видалити з шита і одразу відкрити інший — без крешів.
- [ ] Довга назва (60+ симв.) → лінія обрізається «…», ккал-колонка не з'їдається; badge сканера на місці.
- [ ] Плюрали «N items · X kcal»: 1 / 2 / 5 записів (укр. форми).

**Редагування запису (Edit entry):**
- [ ] Префіл = поточна кількість у поточних юнітах; зберегти → змінюється лише кількість, kcal/макро рахуються з замороженого per-100.
- [ ] Кошик у шиті → підтвердження → видалено, шит закрився.
- [ ] «Зберегти зміни» без правок на seeded/US-даних → перевірити, що кількість не «поїхала» через округлення (кандидат у баги, §18).

**Зміна дня:**
- [ ] Застосунок відкритий через північ (і згорнутий, і на передньому плані) → Today перемикається на новий день, вчорашні записи не «липнуть».
- [ ] Шит кількості відкритий о 23:59, CTA після 00:00 → перевірити день запису і що флоу не зламався.
- [ ] Зміна таймзони → записи НЕ переїжджають між днями (dayKey заморожений); не-грегоріанський календар пристрою — те саме.

**Незмінність історії (ключовий інваріант):**
- [ ] Залогати → змінити калорії/назву продукту в Edit → у щоденнику стара назва і старі kcal.
- [ ] Видалити продукт → записи лишаються, редагування кількості «сирітського» запису далі працює.

## 4. Add food (список, пошук, recents)

- [ ] З Today — fullScreenCover; з день-детейлу — card sheet. Back-кнопка = назва дня («9 July»).
- [ ] Recents: до 8 чипів, останній залогований перший, чип показує останню кількість («60 g · 228 kcal»); зникають при введеному пошуку.
- [ ] Пошук: case-insensitive по назві; порожній результат → «No products match “X”».
- [ ] Сортування: за останнім логуванням/створенням DESC; після логування продукт піднімається вгору.
- [ ] Свайп рядка: Delete + Edit (по 88 pt); алерт видалення продукту каже «Your logged entries stay».
- [ ] Банер AdMob під списком — free + після grace.
- [ ] Після успішного логування шит кількості закривається І сторінка Add food закривається — юзер на екрані дня.

## 5. Форма продукту

- [ ] Режими: New (з логування — з тумблером «Save to My products», дефолт ON), «+» біля MY PRODUCTS (без тумблера), Edit.
- [ ] CTA: тумблер ON → «Save» (зберігає БЕЗ логування); OFF → «Add to today» (логує одразу, кількість = введене Per X; продукт у списку НЕ з'являється, запис переживає перезапуск).
- [ ] CTA активна лише коли: назва непорожня + калорії парсяться + Per > 0.
- [ ] Нулі не префіляться — порожні поля з плейсхолдером «0».
- [ ] «На X»: Per = 50, Calories = 100 → у списку «200 kcal / per 100 g». Каптіон слідує за Per («NUTRITION (PER 30 G)»).
- [ ] Ліміти вводу в кожному полі: «12345»→«1234»; «1,2,3»→«1,2»; «,5»→«0,5»; paste «12.3456»→«12.3»; літери ріжуться.
- [ ] ar-локаль: «١٥٠٫٥» НЕ перетворюється в 1505 (регресія роздільника «٫»).
- [ ] Штрихкод: чип «BARCODE SAVED» тільки після скану; ручна форма поля barcode не має; Edit сканованого показує чип.
- [ ] OFF-продукт без нутрієнтів → картка «No nutrition data yet».
- [ ] Back на брудній формі → «Discard changes?» (в Edit спрацьовує завжди — відома особливість).
- [ ] Секція Vitamins & minerals: згорнута, показує лише трековані, «Track more nutrients» веде в налаштування.

## 6. Кількість (кейпад)

- [ ] Старт завжди 100 канонічних г/мл (не остання кількість). US+г → відкривається «3.5 oz», у базу піде 99.2 г — kcal мають відповідати 99.2, а не 100.
- [ ] Чипи: 50/100/150/200 (метрика) або 1/2/4/8 oz — тап замінює значення.
- [ ] Кейпад: 4 цифри цілої + 1 десяткова, роздільник locale-aware (укр «,», ар «٫»), другий роздільник не вводиться, backspace на останній цифрі → «0», цифра поверх «0» замінює.
- [ ] Жива картка перераховує KCAL/P/F/C на кожне натискання; CTA сіра при 0.
- [ ] Успішний лог: success-хептика, запис = знімок (назва + per-100 + wasScanned), lastQuantity/lastLoggedAt оновлюються тільки для збережених продуктів.

## 7. Сканер + Open Food Facts

**Стани:** scanning (вьюфайндер, лінія) / searching (спінер + код) / found (мить, одразу форма) / notFound («Create manually» + «Scan again») / denied («Open Settings» + «Add manually instead») / offline («Retry» + «Scan again»). Фази перетікають fade 0.2 с; Back працює в будь-якій фазі.

- [ ] ODbL-футер «Data from Open Food Facts» видно у searching/found/notFound (обов'язкова атрибуція).
- [ ] Розпізнаються тільки EAN-13/EAN-8/UPC-E/Code128; QR — НІ.
- [ ] Успіх камерою: хептика + звук 1057, сесія стоп. Debounce 2 с: той самий код удруге — тихо ігнорується; через >2 с — знову.
- [ ] Ручний ввід на симуляторі: без звуку/debounce (навмисно); панель відсутня на реальному девайсі (перевірити на TestFlight).
- [ ] UPC-A/EAN-13: продукт, збережений під 12-значною формою, при скані 13-значної (з нулем) дає локальний хіт — БЕЗ мережі, без близнюка. Чип у формі показує код, за яким продукт реально знайшовся.
- [ ] Denied: перший вхід — системний промпт; відмова → екран з «Open Settings» (не глухий кут). Відомий нюанс: після видачі дозволу в Settings екран лишається denied до перевідкриття сканера (§18).
- [ ] OFF: 404/status≠1 → notFound (це НЕ помилка); Airplane Mode → offline, «Retry» доводить до результату.
- [ ] User-Agent `CalorieTracker/1.0 (com.prxfitness.calorietracker; contact@utr.ua)` присутній (Charles/Proxyman).
- [ ] Basis-детект: напій (л/мл) → форма на ml; сухе → g. Продукт лише з кДж → коректні kcal (÷4.184).
- [ ] Натрій: якщо sodium > salt на картці OFF → береться salt×0.4; у форму йде в мг.
- [ ] Дублікати неможливі: повторне збереження того самого коду оновлює існуючий продукт (один рядок), recency не ламається.
- [ ] OFF-продукт НЕ зберігається автоматично: Back → Discard → у списку і щоденнику нічого (навмисно). Повторний скан незбереженого йде в мережу знову і з'їдає ще один скан.

## 8. Ліміт сканів + rewarded-реклама

Лічильник тікає ТІЛЬКИ коли OFF знайшов новий продукт. Локальний хіт / notFound / denied / manual — безкоштовні. Преміум не тікає.

- [ ] Reset free scans → скан 1 (новий OFF): без реклами, Used = 1.
- [ ] Скан 2 (інший новий): rewarded показується МІЖ пошуком і результатом; «Product found» не видно до закриття реклами.
- [ ] Закрити рекламу достроково → форма однаково відкривається. Реклама не завантажилась → результат одразу. Реклама ніколи не губить скан.
- [ ] Повторний скан збереженого продукту: без реклами, без тіку, одразу кількість.
- [ ] Used = 10 → кнопка Scan відкриває пейвол (сканер не відкривається); логування їжі при цьому доступне.
- [ ] Premium → сканер без ліміту і реклами.
- [ ] Для тесту реклами спершу Settings → Test → «Ads: skip ad-free day» (перші 24 год реклами немає).

## 9. Calendar + 30-денний замок

- [ ] Дефолт — Month; перемикач Week/Month = fade + анімація висоти. Тиждень: заголовок «Jul 6 – 12».
- [ ] Chevron/свайп (поріг 40 pt, горизонталь > вертикаль): сітка їде slide-ом у напрямку кроку; кільця нової сітки наливаються заново.
- [ ] Комірки: з даними — кільце 4 pt + число; майбутні — muted + disabled; сьогодні — зелений диск + жирне число; без цілі калорій — повне сіре кільце.
- [ ] Замок (free): дні старші 30 (включно з сьогодні) — число + lock.fill, БЕЗ кільця; тап → пейвол. Навігація по старих місяцях не обмежена.
- [ ] Агрегати чесні: статистика і Nutrients рахуються ТІЛЬКИ по розблокованих днях (липень: середні лише з 5-го, якщо сьогодні 3 серпня).
- [ ] Повністю замкнений період → CalendarHistoryLockedCard замість статистики; банер, Nutrients і легенда теж зникають; «Unlock history» → пейвол.
- [ ] Статистика: 2×2 картки avg/goal зі смужками в кольорах CalendarRingState; період без записів → «0 / goal».
- [ ] Nutrients card: тільки якщо є середні; «нема даних» ≠ 0 — день без даних нутрієнта не тягне середнє.
- [ ] Банер реклами між статистикою і Nutrients (free + після grace).
- [ ] Купівля преміуму → замки/статистика оновлюються живо, без перезаходу в таб.
- [ ] Після редагування дня в детейлі → back → кільце дня і середні перерахувалися.
- [ ] RTL (ar): свайп у бік читання = наступний період, slide не конфліктує з напрямком свайпу; літери днів ротовані під firstWeekday.
- [ ] Відомі особливості: Month↔Week↔Month може «з'їхати» на попередній місяць; сітка не оновлюється сама опівночі (§18).

## 10. День-детейл (з календаря)

- [ ] Хром: inline «3 серпня», back = назва місяця, таб-бар схований, FAB немає; Add food — card sheet; футер «+ Add food to this day»; хінт про свайп.
- [ ] Банер реклами між картою суми і Logged — тільки тут (Today root без реклами); у порожньому минулому дні банера немає.
- [ ] Порожній минулий день: ТІЛЬКИ сіра картка «Nothing logged this day» + кнопка додати (без кілець/банера/секції Logged).
- [ ] Додати їжу в минулий день → запис лягає саме в той день; після повернення картка суми з'явилась.
- [ ] Нутрієнти дня = набір «на той день» (журнал): вимкнути цукор сьогодні → вчора він лишився; увімкнути новий сьогодні → 10 днів тому його немає; кілька перемикань за день → лишається фінальний стан.
- [ ] Після втрати преміуму історичні дні далі показують преміум-нутрієнти, які тоді трекались.

## 11. Settings

**Структура:** Premium-картка → MY GOALS → UNITS → GENERAL (Language/Reminders/iCloud) → ABOUT → Delete all data → банер → TEST (DEBUG) → футер версії.

- [ ] Premium-картка: free = «Try Premium» + Upgrade → пейвол; premium = «Premium active» + «Manage subscription» (apps.apple.com/account/subscriptions).

## 18. Кандидати в баги з аудиту 2026-08-03 (перевірити/вирішити)

**Середні:**
- Скасування/експірація/рефанд підписки не відображаються до ручного Restore (немає рефрешу entitlement на старті).
- Restore без покупок — нуль фідбеку; Restore, що знімає преміум, — теж.
- Сканер лишається в denied після видачі дозволу в iOS Settings (до перевідкриття).
- Reminders-тумблер при відмові в дозволі мовчки відскакує OFF (немає лінка в Settings).
- Calendar: Month → Week → Month може з'їхати на попередній місяць (anchor drift).
- Calendar не слухає зміну дня: відкритий через північ показує вчорашні «сьогодні»/замки до перемальовки.
- Префіл кількості тихо обрізає/округлює значення → «Зберегти» без правок може змінити дані (особливо >9999 у одиниці показу).

**Дрібні:**
- CTA «Add to today» при логуванні в минулий день (текст).
- Порожній стан пушнутого «сьогодні» каже «Торкніться "+"», хоча FAB там немає.
- Число залишку червоне вже при >100%, кільце amber лише >105% (узгодити з правилом «без червоного»).
- Подвійна хептика: на клавішах кейпада і на успішному лозі (дві success).
- Language → System не показує футноут рестарту; регіональні коди (es-ES, pt-BR, zh-Hans) — ризик «вічного» футноута.
- GoalsCalculatorSheet жорстко cm/kg при US units.
- Немає індикації залишку безкоштовних сканів (ліміт з'являється раптово пейволом).
- ATT-алерт поверх онбордингу.
- Resume онбордингу перераховує план з дефолтів (введені відповіді губляться).
- Кілька свайп-рядків можуть бути відкриті одночасно; після Cancel рядок лишається відкритим.
- Delete all data скидає unitSystem на дефолт пристрою (не на вибір юзера) і повертає 10 сканів (лупхол).
- Застарілі коменти: «3 free scans» в UserSettings, «premium is active» в CalorieTrackerApp.
