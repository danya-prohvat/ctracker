# TEST PLAN — Calorie Tracker (Manual QA)

## 1. Перший запуск і онбординг

### 1.1 Дефолти за пристроєм

- [ ] Регіон US → чиста інсталяція → Settings → Units = US (oz / fl oz)
- [ ] Регіон UK / UA / DE / FR / JP → Units = Metric
- [ ] Регіон US → на кроці зріст/вага тумблер уже стоїть на ft · lbs
- [ ] Вручну перемкнути Units на протилежне → вбити й запустити → лишився вибір юзера, не дефолт регіону
- [ ] Чиста інсталяція → інтерфейс мовою пристрою; у Settings рядок Language показує «System», футноута під ним немає
- [ ] Чиста інсталяція (Test не чіпати) → Settings, Calendar, Add food — жодного банера (перша доба без реклами)

### 1.2 Кроки онбордингу

Порядок (7): стать → вік → зріст/вага → активність → цільова вага → «Calculating…» → «Your plan» → Continue.

- [ ] Капсула прогресу зверху росте на кожному кроці
- [ ] На кожному кроці є Skip; кнопки «Назад» немає (очікувано)
- [ ] Стать і активність переходять далі самі через ~0.2 с після вибору
- [ ] Для статі є варіант «Prefer not to say»
- [ ] Вік — колесо 10–99, дефолт 25
- [ ] Діапазони коліс: 120–220 см / 35–200 кг; 4′0″–7′0″ / 77–440 lbs
- [ ] Тумблер юнітів пише в налаштування одразу: перемкнути на ft · lbs → Skip до кінця → закрити пейвол → Settings → Units = US
- [ ] 175 см / 70 кг → перемкнути на ft·lbs → назад на cm·kg → колеса приблизно на тих самих значеннях (дрейф ±0.5 кг допустимий)
- [ ] Усі кроки через Skip → Settings → Goals = 2000 kcal / 150 P / 67 F / 200 C
- [ ] Заповнити всі кроки → «Your plan» → Continue → Goals = числа з екрана «Your plan»
- [ ] На «Your plan» тап у поле калорій → ввести 2500 → НЕ натискаючи Done, одразу Continue → Goals = 2500
- [ ] ⚠️ На «Your plan» змінити калорії на 2500 → Skip → Goals = 2000 (Skip стирає правки)

### 1.3 Пейвол і системні промпти

- [ ] Після Finish або Skip ~1 с видно Today → зверху виїжджає пейвол на весь екран
- [ ] Свайп-даун пейвол після онбордингу НЕ закриває; через 1.5 с з'являється X — єдиний вихід
- [ ] Якщо преміум уже активний (відновився з iCloud) — пейвол після онбордингу не показується
- [ ] Через ~0.7 с після старту — системний ATT-алерт «Allow … to track…», можливо поверх першого кроку; будь-яка відповідь → онбординг продовжується нормально
- [ ] Одразу після ATT — системний промпт нотифікацій (Reminders увімкнені за замовчуванням); «Don't Allow» → тумблер Reminders у Settings стає OFF
- [ ] Обидва промпти показуються один раз за життя інсталяції

### 1.4 Відновлення перерваного онбордингу (відповіді зберігаються)

- [ ] Female / 40 / 160 см / 55 кг → на кроці активність вбити застосунок → запуск → онбординг відкрився на тому ж кроці
- [ ] Далі Sedentary → «Your plan» ≈ 1430 kcal (з введених відповідей, а не ≈ 2400 з дефолтів)
- [ ] Settings → Goals → «Calculate for me» префілений цими ж відповідями
- [ ] Вбити застосунок під час «Calculating…» (1.8 с) → запуск → знову «Calculating…», потім «Your plan»

### 1.5 Онбординг і калькулятор ділять профіль

- [ ] Пройти онбординг з відповідями → Goals → «Calculate for me» відкрився з цими відповідями
- [ ] У калькуляторі змінити вагу → Apply → `-resetOnboarding 1` → онбординг стартує з профілю: картки статі й активності підсвічені (тап по підсвіченій веде далі), колеса на збережених значеннях, вага — та, що застосував калькулятор, цільова вага — збережена
- [ ] Delete all data → калькулятор порожній, онбординг не повертається

### 1.6 Холодний старт

- [ ] Чиста інсталяція → запуск з іконки (не з Xcode) → одразу перший крок онбордингу, без порожнього білого/сірого кадру

## 2. Today і щоденник

### 2.1 Базовий флоу

- [ ] FAB «+» → New product → «Test», Calories 200, Protein 10 → Save → у My products тапнути «Test» → у кейпаді лишити 100 → Log → шит закрився, ти на Today
- [ ] У списку рядок «Test · 100 g · 200 kcal», кільце калорій наповнилось, числа «перекрутились» анімацією (не стрибок)
- [ ] Тап по рядку «Test» → у кейпаді 50 → Save changes → рядок 50 g · 100 kcal, кільця і «залишилось» перерахувались
- [ ] Свайп рядка вліво → Delete → підтвердити → рядок зник з анімацією, суми зменшились

### 2.2 Вигляд

- [ ] Залогати 5+ записів → скрол униз → великий заголовок «Today» стає маленьким по центру; підзаголовок з датою — тільки на iOS 26+
- [ ] Макет: велике кільце калорій з підписом «залишилось сьогодні»; під ним три макро-кільця з підписом «з 150 g» (ціль); FAB «+» з градієнтом внизу праворуч; таб-бар видимий
- [ ] Таб Calendar → назад на Today → кільця наповнюються «пружинкою» (з невеликим перельотом)
- [ ] Залогати щось → числа міняються анімацією прокрутки цифр
- [ ] Тап по зоні макро-кілець у день із записами → під кільцями «P X% · F Y% · C Z% of calories»
- [ ] Тап по зоні макро-кілець у порожній день → нічого не з'являється
- [ ] Settings → Goals → Net carbs ON → на Today рядок «Net carbs: X»
- [ ] Залогати продукт без клітковини → Net carbs «—», а не «0»
- [ ] Продукт з клітковиною 20 г і вуглеводами 10 г → Net carbs = 0, не мінус

### 2.3 Кольори кілець (ніколи не червоні)

- [ ] Калорій менше цілі → дуга калорій зелена, дуги P/F/C у своїх кольорах; трек (незаповнена частина) того самого кольору, але блідий
- [ ] Ціль 2000, залогати 3000 kcal → дуга і трек калорій amber; дуга зупиняється на 100%, другого витка немає
- [ ] Перебрати тільки білок (продукт із 300 г білка) → amber лише кільце білка, інші у своїх кольорах
- [ ] ⚠️ Рівно 2050 kcal при цілі 2000 → число «залишилось» уже червоне (мінус), а кільце ще зелене (розбіжність 100–105%)
- [ ] Після кожного з цих тестів комірка «сьогодні» в Calendar: <80% — сіре кільце, 80–105% — зелене, >105% — amber

### 2.4 Вітаміни й мінерали (секція нижче на Today)

- [ ] Тап по заголовку секції → розкривається плавно, шеврон повертається на 180°; у заголовку «N tracked»
- [ ] Продукт з Vitamin C = 200 мг → залогати 100 г → Vitamin C ≥100% → зелений чекмарк
- [ ] Продукт із Sodium = 2500 мг → залогати 100 г → смужка червона; у підписі ПІД назвою «Limit · +200 mg over» червоним; справа лише «2,500 / 2,300 mg»; чекмарка немає
- [ ] Sodium у 90–100% норми → смужка amber
- [ ] Limit-нутрієнти (sodium, sugar, saturated fat, trans fat, cholesterol, caffeine) мають підпис «Limit», решта — «Goal»
- [ ] iPhone SE / 14, мова de → pl → ru → uk → ro, Тестові дані → Calendar → день 5 днів тому (насичені жири 23,7 / 20 г) → Nutrients: назва («Gesättigte Fettsäuren», «Насыщенные жиры») не обрізана, значення справа не стиснуте, «Limit · +3,7 darüber» видно повністю під назвою (переноситься на другий рядок, не ріжеться)
- [ ] Те саме в календарі (Nutrients card за період, де середнє натрію/цукру вище норми)
- [ ] Продукт без жодного мікронутрієнта → у нутрієнтів «—» без смужки
- [ ] Порожній день → «0 / ціль» із тонкою порожньою смужкою
- [ ] Долити продукт з Vitamin C → «—» у Vitamin C став числом
- [ ] Продукт із trans fat = 1 г → тільки «1 g», без «/ ціль» і без смужки (норми немає)

### 2.5 Записи щоденника

- [ ] Свайп рядка вліво не до кінця → з'являється Delete шириною ~88 pt
- [ ] Тап по відкритому (свайпнутому) рядку → рядок закривається, редактор НЕ відкривається
- [ ] Лонг-тап по рядку → контекст-меню Edit / Delete
- [ ] Delete будь-яким шляхом → алерт з назвою продукту в заголовку і «…Цю дію не можна скасувати»
- [ ] Cancel в алерті → рядок лишається відкритим (свайпнутим)
- [ ] Видалити всі записи по одному → кожне видалення анімоване; після останнього — плавна заміна на зелену картку порожнього стану, підпис «0 items · 0 kcal»
- [ ] 5 записів → швидко видалити 3–4 підряд без пауз → без крешів і «завислих» рядків
- [ ] Відкрити запис → видалити кошиком у шиті → одразу відкрити інший → без крешів
- [ ] Назва 60+ символів → обрізана «…» в один рядок, колонка kcal не з'їхала; у сканованого продукту іконка сканера на місці
- [ ] Мова uk → 1, 2, 5 записів → «1 запис», «2 записи», «5 записів» + «X ккал»

### 2.6 Редагування запису (тап по рядку)

- [ ] Залогати «Test» 100 г (200 kcal) → Add food → свайп «Test» → Edit → Calories 999 → Save → Today → тап запис → кейпад стартував зі 100 (поточна кількість)
- [ ] Змінити на 200 → Save changes → запис 200 g · 400 kcal (зі знімка 200/100 г, а не з нових 999)
- [ ] Тап запис → іконка кошика → підтвердити → запис видалено, шит закрився
- [ ] Тестові дані → Units = US → тап по будь-якому запису → нічого не натискати → Save changes → кількість у рядку абсолютно та сама (не «округлилась» на 0.1–1%)
- [ ] Тап запис → натиснути одну цифру → стерти backspace-ом (текст початковий) → Save changes → збережено точне початкове значення
- [ ] ⚠️ Units = US → залогати 9999 oz → Units = Metric → тап запис → у кейпаді і на живій картці значення обрізане до 4 цифр, у рядку щоденника реальне (283 кг); Save без правок зберігає реальне

### 2.7 Зміна дня (див. «Північ» у §0.3)

- [ ] Today на екрані → перевести дату на завтра → Today показує новий порожній день, учорашні записи не лишились
- [ ] Згорнути → перевести дату → розгорнути → те саме
- [ ] Під час ресету: кільця анімуються з нуля, скрол стрибає вгору, розкриті секції згортаються (очікувано)
- [ ] ⚠️ Відкрити Add food (або кейпад, або редагування) → перевести дату на завтра → шит зникає, введене губиться; головне — без креша. Log до переводу дати → запис лягає у старий день
- [ ] 10 разів поспіль згорнути/розгорнути → кільця не миготять, скрол не стрибає, нічого не гальмує
- [ ] Залогати → Time Zone на +10 год (щоб «зараз» стало завтра) → повернутись → запис лишився у своєму дні
- [ ] Змінити Calendar пристрою на Buddhist/Japanese → записи в тих самих днях
- [ ] Застосунок на Today, час ~22:00 → згорнути (не вбивати) → Time Zone на +10 год → розгорнути → Today показує НОВИЙ порожній день, сітка Calendar підсвічує той самий новий день; новий запис лягає в новий день

### 2.8 Незмінність історії (ключовий інваріант)

- [ ] Залогати «Test» (200 kcal) → Add food → свайп «Test» → Edit → «Test2», Calories 500 → Save → у щоденнику досі «Test · 200 kcal»
- [ ] Залогати «Test» → Add food → свайп → Delete → підтвердити → Today → тап запис → змінити кількість → Save → запис живий, редагування працює

## 3. Add food (список, пошук, recents)

Відкривається з Today через FAB «+» або з день-детейлу календаря через «+ Add food to this day».

### 3.1 Подання і навігація

- [ ] Today → FAB → відкривається на весь екран
- [ ] Calendar → минулий день → Add food → картка-шит знизу; Back підписаний назвою дня («9 July»)
- [ ] Add food → продукт → Log → закрився і кейпад, і Add food — ти одразу на Today (або на день-детейлі, звідки заходив)

### 3.2 Recents

- [ ] Залогати 3 різні продукти з різною кількістю → зверху ряд чипів Recents, останній залогований перший
- [ ] На чипі остання кількість і kcal («60 g · 228 kcal»); максимум 8 чипів
- [ ] Почати вводити в пошук → чипи зникають
- [ ] Тап чип → кейпад відкривається з базової кількості продукту (Per X із форми; 100 для сканованих/сідованих), а НЕ з останніх 60 г (очікувано)

### 3.3 Пошук і сортування

- [ ] «test» для «Test» (інший регістр) → знаходить
- [ ] «zzzzz» → «No products match "zzzzz"»
- [ ] ⚠️ Один пробіл у пошуку → Recents зникли, але список повний і «No products match» не показано
- [ ] Список за останнім логуванням/створенням (нові зверху); залогати продукт із середини → він піднявся на перше місце

### 3.4 Свайп продукту

- [ ] Свайп рядка вліво → дві кнопки Delete і Edit (по ~88 pt)
- [ ] Delete → алерт із текстом «Your logged entries stay»
- [ ] Тап продукт → кейпад → потягнути шит кейпада вниз не до кінця (або на iPad, де шит не закриває список) → свайпнути той самий продукт → Delete → підтвердити → повернутись у кейпад → Log → лог проходить, запис є, чип зник з Recents, без крешів (на iPhone, якщо недосяжно — пропустити з поміткою)

### 3.5 Картки Scan / New product і банер

- [ ] Преміум OFF + Реклама ON → прокрутити під список My products → банер AdMob
- [ ] Преміум OFF → Reset free scans → під «Scan» дрібний сірий підпис «10 free left»
- [ ] Після одного зарахованого скану → «9 free left»; після вичерпання пулу → «3 of 3 today» → «2 of 3 today» … «0 of 3 today»
- [ ] Преміум ON → підпису немає
- [ ] Мова de / fi / uk → підпис стискається в один рядок, картка не росте і не ламає ряд із «New product»

## 4. Форма продукту

Три способи відкрити: (1) Add food → картка **New product**; (2) Add food → «+» біля заголовка MY PRODUCTS; (3) Add food → свайп продукту вліво → Edit.

### 4.1 Режими і кнопки

- [ ] (1) Внизу скролу дві кнопки: основна «Save to My products» і текстова «Log today only» (з детейлу минулого дня — «Log once»); тумблера немає
- [ ] (2) Лише «Save», другорядної кнопки немає
- [ ] (3) Edit — поля префілені
- [ ] Кнопки — останній блок скролу форми, не прикріплений бар; клавіатура їх не перекриває
- [ ] (1) заповнити → «Save to My products» → продукт у списку, у щоденнику нічого (кількість обирається зі списку)
- [ ] (1) Per = 80 → заповнити → «Log today only» → запис 80 г одразу в щоденнику, продукту в My products НЕМАЄ; після вбити/запустити запис на місці

### 4.2 Валідність і плейсхолдери

- [ ] Порожня назва → CTA неактивна
- [ ] Назва є, калорії порожні → неактивна
- [ ] Назва + калорії, Per = 0 → неактивна
- [ ] ⚠️ Назва + Calories «0», Per 100 → активна, продукт на 0 kcal створюється (вирішити, чи це ок)
- [ ] У новій формі числові поля порожні із сірим «0», а не заповнені нулями

### 4.3 Per X

- [ ] Per = 50, Calories = 100 → Save → у списку «200 kcal / per 100 g»; тап продукт → кейпад стартує з 50 g
- [ ] Під час вводу Per заголовок секції слідує за значенням: «NUTRITION (PER 50 G)»
- [ ] ⚠️ Edit продукту «на 100» (200 kcal) → Per змінити зі 100 на 50 → Save → у списку 400 kcal (усі значення подвоїлись; Per каже «на скільки» введені числа)
- [ ] New product → Per = 30, Calories = 100, Protein = 7 → Save (у списку 333,3 kcal / per 100 g) → Edit → форма показує Per = 30, Calories = 100, Protein = 7; заголовок «NUTRITION (PER 30 G)»
- [ ] Нічого не міняти → Save → знову Edit → значення в списку не змінились
- [ ] Edit сканованого або сідованого продукту → відкривається як Per = 100

### 4.4 Ліміти вводу

- [ ] «12345» → «1234»
- [ ] «1,2,3» → «1,2»
- [ ] «,5» → «0,5»
- [ ] Вставити «12.3456» → «12.3»
- [ ] Літери не з'являються
- [ ] Language → العربية → Calories «١٥٠٫٥» → Save → у списку 150.5, а не 1505

### 4.5 Штрихкод і дані з OFF

- [ ] New product вручну → поля barcode і чипа немає
- [ ] Форма після скану і Edit сканованого → чип «BARCODE SAVED»
- [ ] Скан продукту без жодного макро в OFF → картка «No nutrition data yet» (тільки коли всі 4 макро нульові І мікро порожні)
- [ ] Продукт з одним натрієм → порожня форма без картки

### 4.6 Discard changes

- [ ] New product → ввести назву → Back → алерт «Discard changes?»
- [ ] Edit існуючого → нічого не міняти → Back → закривається мовчки
- [ ] New product → ввести назву → свайп-даун → шит НЕ закривається
- [ ] New product → нічого не вводити → свайп-даун → закривається

### 4.7 Vitamins & minerals у формі

- [ ] Секція згорнута; після розкриття — тільки увімкнені (трековані) нутрієнти
- [ ] «Track more nutrients» веде в Settings → нутрієнти
- [ ] ⚠️ У Vitamin C ввести 0 → лічильник «N added» рахує його як доданий, але на Today у Vitamin C «—» (нулі не зберігаються)

## 5. Кількість (кейпад)

Відкривається тапом по продукту в Add food.

### 5.1 Стартове значення

- [ ] Metric → продукт «на 100» → «100 g»
- [ ] Продукт із Per = 30 → «30 g»
- [ ] Сканований або сідований продукт → «100 g»
- [ ] US → продукт «на 100» у грамах → «3.5 oz»
- [ ] Залогати продукт (Per = 30) 60 г → знову тапнути → знову «30 g» (остання кількість НІКОЛИ не префілиться, очікувано)
- [ ] US → продукт «на 100» → нічого не натискати → Log → Metric → у рядку рівно «100 g» (не 99.2); жива картка в кейпаді при цьому рахувала з 3.5 oz = 99.2 г — різниця ~0.8% допустима

### 5.2 Чипи і клавіші

- [ ] Чипи 50 / 100 / 150 / 200 (Metric) або 1 / 2 / 4 / 8 oz (US); тап повністю замінює значення
- [ ] Ввести 12345 → максимум 4 цифри цілої + 1 десяткова
- [ ] 1,2,3 → другий роздільник не вводиться; роздільник locale-aware (uk «,», ar «٫»)
- [ ] Backspace до кінця → на останній цифрі дає «0»
- [ ] На «0» натиснути 5 → «5», не «05»
- [ ] Кожне натискання → KCAL / P / F / C на картці перераховуються; при 0 кнопка Log сіра

### 5.3 Успішний лог

- [ ] Log → коротка success-вібрація (реальний пристрій)
- [ ] У щоденнику запис зі знімком (назва, per-100, ознака «сканований»)
- [ ] Продукт, залогований через «Log today only» — у Recents не з'являється (його немає в списку)

## 6. Сканер + Open Food Facts

Відкривається: Add food → картка **Scan**. Без камери код вводиться через «Enter code manually» під панеллю статусу (на емуляторі це єдиний шлях).

**Фази (10):** requestingPermission (темний порожній екран із хедером, поки не відповів на промпт камери — не креш, очікувано) → scanning (вьюфайндер, лінія) → searching (спінер + код) → found (мить, одразу форма) або rewardOffer («Product found» + «Watch ad» / «Go Premium», §7) або handedOff (локальний хіт — мить порожнього екрана до кейпада, очікувано) або notFound («Create manually» + «Scan again») або offline («Retry» + «Scan again»); окремо denied («Open Settings» + «Add manually instead») і limitReached (§7). Фази перетікають fade 0.2 с; Back працює в будь-якій.

### 6.1 Базовий скан

- [ ] `5449000000996` → форма префілена (Coca-Cola, kcal, макро, чип BARCODE SAVED) → Save → продукт у My products
- [ ] `4444444444448` → notFound (це НЕ помилка)
- [ ] Airplane Mode → робочий код → offline → вимкнути Airplane → «Retry» → форма
- [ ] У searching / found / notFound і на оффері «Watch ad» внизу «Data from Open Food Facts»
- [ ] В offline / denied / limitReached футера ODbL немає (очікувано)
- [ ] `5449000000996` (напій) → форма на ml; `3017620422003` (сухе) → g
- [ ] Продукт лише з kJ на OFF → kcal порахувались (÷4.184)
- [ ] Продукт, де в OFF є salt, але нема sodium (або sodium > salt) → Sodium = salt × 0.4 (мг)
- [ ] Нутрієнти, які в OFF стоять як 0 → у формі порожні («—»), не 0 (очікувано)

### 6.2 Реальний пристрій: коди, звук, debounce

- [ ] QR-код не розпізнається взагалі
- [ ] UPC-E (8-значний з упаковки US) зчитується, але на OFF дає notFound (очікувано)
- [ ] Code128 з літерами → без креша, довгий код не ламає верстку чипа
- [ ] Робочий код → вібрація + системний «тік», камера зупинилась
- [ ] Вигаданий код → notFound → «Scan again» → протягом 2 с той самий код → нічого не відбувається (виглядає як «не сканує» — навмисно)
- [ ] Через >2 с той самий код → спрацьовує

### 6.3 Ручний ввід коду

- [ ] «Enter code manually» є у фазах scanning і denied; у пошуку, результатах і на екрані ліміту його немає
- [ ] Шит із полем «Barcode», цифрова клавіатура з автофокусом
- [ ] Вставити «abc 4820-000» → лишаються тільки цифри «4820000»
- [ ] Більше 14 цифр не вводиться
- [ ] 7 цифр → «Look up code» неактивна, підказка нейтральна
- [ ] 10 цифр або `4820000123456` (не сходиться контрольна) → неактивна, підказка «That doesn't look like a valid barcode»
- [ ] `5449000000996` → кнопка активна → шит закривається → пошук тим самим шляхом, що з камери (своя база → OFF, лічильник і оффер реклами тотожні), без звуку і debounce
- [ ] `036000291452` (UPC-A) шукається як `0036000291452`
- [ ] `12345670` (8 цифр) приймається без перевірки
- [ ] Закрити шит свайпом без коду → сканер продовжує розпізнавати
- [ ] Поки шит відкритий, код з камери ігнорується
- [ ] Debug-бар «Barcode / Look up code» у нижньому барі більше не існує

### 6.4 Локальна база, дублікати, UPC-A ↔ EAN-13

- [ ] Реальний 12-значний UPC-A → Save → той самий код із провідним нулем (13 цифр) → без мережі, без близнюка — одразу кейпад кількості
- [ ] `3017620422003` → Save → Edit → змінити назву → Save → знову `3017620422003` → локальний хіт (одразу кейпад, без мережі); у списку ОДИН продукт із цим кодом, угорі
- [ ] Новий код → на префілд-формі нічого не чіпати → Back → закрилось мовчки (без Discard), у списку і щоденнику нічого
- [ ] Той самий код знову → знову йде в мережу і знову витрачає безкоштовний скан (очікувано)
- [ ] Через проксі: `0` + 12-значний → у запитах заголовок `User-Agent: CalorieTracker/1.0 (com.prxfitness.calorietracker; contact@utr.ua)`; запитів два — з 13 і з 12 цифрами

### 6.5 Відмова в камері

- [ ] Чиста інсталяція → Scan → «Don't Allow» → екран denied: «Open Settings» (веде в налаштування застосунку), «Add manually instead», посилання «Enter code manually» (ручний код працює без камери)
- [ ] ⚠️ Дозволити камеру в Settings і повернутись → екран лишається denied до перевідкриття сканера

### 6.6 Скасування пошуку (повільна мережа — §0.3)

- [ ] Реклама ON, Used ≥ 1 → повільна мережа → новий код → поки спінер — Back → ти в Add food; оффер і реклама не з'являються; Used не збільшився; форма не відкривається
- [ ] Одразу знову Scan → чиста фаза scanning, старий результат не «доганяє»
- [ ] Airplane Mode → код → під час searching Back → знову Scan → екран offline від скасованого запиту не прилітає
- [ ] Airplane Mode → код → offline → вимкнути Airplane → швидко «Retry» 5 разів → один результат, один оффер «Watch ad» (якщо гейт), один тік Used
- [ ] На оффері «Watch ad» → під час реклами згорнути → повернутись → закрити рекламу → форма відкрилась, Used не подвоївся
- [ ] Network Link Conditioner (Edge/3G) → новий код → Back за мить до зникнення спінера, повторити 5–10 разів → ти в Add food, форма НЕ відкривається, Used не росте, реклама не вискакує

## 7. Ліміт сканів + rewarded-реклама

Правило: безкоштовний юзер має **вітальний пул 10** зарахованих сканів, після нього — **3 на локальний день**; Преміум — без лічильників і реклами. Лічильник тікає ТІЛЬКИ коли OFF знайшов новий продукт (при розкритті результату, після реклами). Локальний хіт / notFound / denied / ручне створення — безкоштовні. Реклама opt-in: з 2-го зарахованого скану (і на кожному скані денної квоти) результат притримується екраном «Product found» з «Watch ad» / «Go Premium».

**Підготовка:** Преміум OFF, Реклама ON, Reset free scans. НЕ використовувати `-initialAddRoute scan`. Потрібно ≥14 різних робочих кодів.

### 7.1 Пул 10

- [ ] Скан 1 (новий код) → оффера й реклами немає, форма одразу; Used = 1; картка Scan «9 free left»
- [ ] Скан 2 → після спінера екран із зеленим чекмарком «Product found», підпис «Watch a short ad to open it, or go Premium to scan ad-free», зелена «Watch ad» з іконкою play, напівпрозора «Go Premium», внизу футер ODbL; вьюфайндера немає; форма НЕ відкривається сама
- [ ] «Watch ad» → rewarded-реклама → закрити → форма; Used = 2 лише після розкриття
- [ ] Гейт = Used ≥ 1: Преміум ON → OFF при Used = 1 → наступний скан одразу з оффером
- [ ] «Watch ad» → закрити рекламу достроково → форма однаково відкривається
- [ ] Відкрити сканер і ввести код МИТТЄВО (реклама не встигла завантажитись) → оффера немає, форма одразу (реклама не готова = безкоштовно)
- [ ] На оффері Back → ти в Add food, форми немає, Used не тікнув
- [ ] «Go Premium» → пейвол ПОВЕРХ сканера → закрити свайпом → ти знову на оффері з «Watch ad»
- [ ] «Go Premium» → купити → пейвол закрився → форма одразу без реклами; Used не змінився
- [ ] Після реклами відкрилась форма → Back → Test → Used уже +1 (Discard скан не повертає, очікувано)
- [ ] Зберегти продукт зі скану → знову його код → без оффера, без тіку, одразу кейпад
- [ ] «Ads: restart ad-free day» → новий код → оффера немає (форма одразу), але Used тікнув; «skip ad-free day» → оффер уже на наступному скані
- [ ] Пул вичерпано ще в grace → 3 денні скани того ж дня теж без реклами (до 13 безрекламних у першу добу — очікувано)

### 7.2 Денна квота

- [ ] Довести Used до 10 → картка «3 of 3 today»; Scan відкриває звичайний сканер (НЕ пейвол)
- [ ] Кожен денний скан іде через оффер «Watch ad»; після третього картка «0 of 3 today»
- [ ] Наступний тап Scan → сканер одразу на екрані «Daily scan limit reached»: пісочний годинник, «You've used today's 3 free scans. Come back tomorrow…», зелена «Unlock unlimited scans», сіра «Add manually instead»; камери і «Enter code manually» немає; Back працює; логування їжі працює; Test: «Used: 10 · today 3»
- [ ] «Add manually instead» → сканер закрився, порожня форма New product без чипа BARCODE
- [ ] «Unlock unlimited scans» → закрити пейвол свайпом → ти знову на екрані ліміту
- [ ] «Unlock unlimited scans» → купити → пейвол закрився → на місці ліміту стартувала камера (scanning) без перевідкриття сканера
- [ ] При «0 of 3 today» → Північ → Add food → «3 of 3 today», Scan знову працює (з оффером)
- [ ] Перевести дату НАЗАД на день → теж «3 of 3 today» (лічильник прив'язаний до ключа дня, не до «завтра»)

### 7.3 Скидання, преміум, синк

- [ ] Test → «Reset free scans» (нота «Used: 10 · today 2») → нота «Used: 0 · today 0», картка «10 free left»
- [ ] «Delete all data» лічильники НЕ скидає — єдиний шлях обнулити = ця debug-кнопка
- [ ] Used = 10, today = 3 → Преміум ON → картка без підпису, сканер відкривається (без екрана ліміту), оффера немає, 3 нових коди не збільшують лічильники
- [ ] Преміум OFF → картка знову «0 of 3 today» (лічильники продовжують з того місця)
- [ ] iCloud ON на двох пристроях → на A витратити 2 денні скани → почекати → на B картка «1 of 3 today» (квота спільна на Apple ID; grace-доба per-device)

## 8. Calendar + 30-денний замок

Підготовка: Тестові дані (є записи глибше 30 днів). Преміум OFF для тестів замка.

### 8.1 Режими і навігація

- [ ] Дефолт Month; перемикання Week/Month — fade + плавна зміна висоти
- [ ] У Week заголовок виду «Jul 6 – 12»
- [ ] ⚠️ Month → Week відкриває тиждень із 1-м числом місяця, а не поточний (для не-поточного місяця)
- [ ] ⚠️ Month → Week → Month кілька разів → може «з'їхати» на попередній місяць (anchor drift)
- [ ] Chevron-и і горизонтальний свайп → сітка їде slide-ом у напрямку кроку; кільця нової сітки наливаються заново
- [ ] Діагональний свайп не «з'їдає» тап по комірці; короткий свайп (<40 pt) не гортає

### 8.2 Комірки

- [ ] День з даними — кільце + число; майбутні дні — бліді і не тапаються
- [ ] Сьогодні: зелений диск + жирне число + живе кільце; при <80% кільце СІРЕ (не баг); у порожній день кільце з порожнім треком (очікувано)
- [ ] У минулий день залогати тільки продукт на 0 kcal → кільце без заповнення, але число НЕ бліде (відрізняється від «немає записів»)
- [ ] Тап по розблокованому дню без записів → детейл відкривається (⚠️ хінт каже «Tap a day with a ring» — неточність)
- [ ] Прибрати ціль калорій неможливо (дефолт 2000) → повне сіре кільце не відтворити (очікувано)

### 8.3 Замок

- [ ] Преміум OFF → дні старші 30 (рахуючи сьогодні) з даними: звичайне кільце + число + маленький бейдж-замок на кільці; порожні заблоковані дні — голе приглушене число
- [ ] Тап по замкненому дню → пейвол
- [ ] Гортати в минуле і майбутнє можна без обмежень; у майбутньому всі дні неактивні, статистика «0 / goal»
- [ ] Місяць, частково накритий замком → avg і картка Nutrients порахована ТІЛЬКИ по розблокованих днях (сьогодні 3 серпня → липень з 5-го)
- [ ] Місяць повністю старший 30 днів (і те саме у Week) → замість статистики картка «історія за замком» з «Unlock history» → пейвол; банер, Nutrients і легенда зникли
- [ ] Free → місяць із замкненими днями → тап замкнений день → купити на пейволі → ти на тому ж місяці: замки зникли, кільця з'явились, статистика перерахувалась одразу

### 8.4 Статистика і Nutrients

- [ ] 2×2 картки на періоді з даними: avg / goal зі смужками (сірий / зелений / amber); без записів «0 / goal»
- [ ] Картка Nutrients є лише коли є середні; день без даних нутрієнта не тягне середнє вниз
- [ ] Порівняння «середнє за період vs ДЕННА норма» (очікувано)
- [ ] Преміум OFF + Реклама ON → банер між статистикою і Nutrients
- [ ] Тап день → у детейлі додати/видалити запис → Back → кільце дня і avg оновились

### 8.5 RTL

- [ ] Language → العربية → свайп у бік читання = наступний період; slide їде в правильний бік
- [ ] Літери днів тижня починаються з правильного дня (firstWeekday); порожні клітинки на початку місяця на правильному краї

### 8.6 Зміна дня

- [ ] Таб Calendar на екрані → перевести дату на завтра → вчорашній день втратив зелений диск, новий отримав диск + порожнє кільце
- [ ] Згорнути о 23:59 → перевести → розгорнути → те саме
- [ ] Преміум OFF → найстаріший розблокований день з даними → Північ → день отримав замок, його ккал зникли з avg/Nutrients без перезаходу в таб
- [ ] Преміум OFF → місяць, де розблокований тільки останній день → Північ → статистика живо змінилась на картку замка
- [ ] Дата 31-ше 23:59 → перевести на 1-ше → сітка лишається на старому місяці, маркер «сьогодні» з неї зникає; крок вперед показує новий місяць з маркером (очікувано)
- [ ] Calendar → тап сьогодні → Північ → підпис «remaining today» → «remaining that day»; порожній день змінює зелену картку на сіру; «Add food to this day» додає у ВЧОРАШНІЙ (відкритий) день
- [ ] Date & Time → зона за межу доби → сітка й замки перемалювались, записи в тих самих днях
