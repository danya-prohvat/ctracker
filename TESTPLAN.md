## 2. Перший запуск і онбординг

- [ ] Мова = мова пристрою, рядок Language = «System» без футноута.
- [ ] Перші 24 год після інсталу — жодної реклами ніде (grace period; якір відліку — див. §17).

**Кроки (7):** стать (авто-перехід 0.2 с; є «Prefer not to say») → вік (wheel 10–99, дефолт 25) → зріст/вага (тумблер юнітів; метрика 120–220 см / 35–200 кг, імперія 4′0″–7′0″ / 77–440 lbs) → активність (4 картки, авто-перехід) → цільова вага (підпис «about N weeks», темп 0.5 кг/тиж) → «Calculating…» 1.8 с → «Your plan» (редактор плану) → Continue.

- [ ] Тумблер юнітів пише в Settings **одразу**: перемкнути на ft·lbs → Skip → Settings → Units = US.
- [ ] Перемикання юнітів туди-сюди на кроці 3 (cm·kg → ft·lbs → cm·kg): значення на колесах не «тікає» помітно (конвертаційний дрейф ±0.5 кг допустимий).
- [ ] Skip: цілі лишаються дефолтними (2000/150/67/200). Finish: цілі з редактора плану записані.
- [ ] ⚠️ Skip на кроці «Your plan» (після редагування плану) → відредаговані значення СТИРАЮТЬСЯ, цілі дефолтні (§18).
- [ ] Ввести значення в редакторі плану і одразу Continue (без Done на клавіатурі) → введене значення записалось у цілі.
- [ ] На US-локалі онбординг стартує в імперії.
- [ ] Після finish/skip: ~1 с на Today → пейвол у fullScreenCover (єдиний вихід — X через 1.5 с, свайпа немає).
- [ ] ATT-алерт прилітає на першій активації (~0.7 с) — може лягти поверх онбордингу; переконатися, що флоу не ламається.
- [ ] Перерваний онбординг (вбити застосунок на кроці 4–6) → відновлюється на тому кроці; план при цьому перераховується з дефолтів (§18). Вбити на «Calculating…» → перезапуск знову показує Calculating і доводить до «Your plan».
- [ ] Чиста інсталяція, холодний старт → кавер онбордингу без блимання порожнім першим фреймом.

## 3. Today і щоденник

**Вигляд:**
- [ ] Великий заголовок «Today» злипається в inline при скролі; підзаголовок з датою — тільки iOS 26+.
- [ ] Кільце калорій 132 pt + «залишилось сьогодні»; три макро-кільця з «з 150 g»; FAB «+» з градієнтом; таб-бар видимий.
- [ ] Кільця заповнюються пружинкою при появі; числа — `.numericText`-анімація.
- [ ] Тап по зоні макро-кілець → рядок «P X% · F Y% · C Z% of calories»; з'являється лише коли калорій за день > 0 (порожній день або день з 0 kcal — не з'являється).
- [ ] Net carbs (якщо ввімкнено в Goals): рядок «Net carbs: X»; продукт без даних клітковини → «—», не «0»; клітковина > вуглеводів → 0, не мінус.

**Кольори (ніколи не червоні кільця):**
- [ ] < 105% цілі → дуга акцентна (калорії зелена, P/F/C у своїх кольорах), трек = той самий колір 18%.
- [ ] > 105% → дуга І трек amber; дуга обрізана на 100% (без другого витка). Кожне макро-кільце має свій незалежний поріг.
- [ ] 100–105%: число залишку вже червоне, кільце ще зелене (задокументована розбіжність — §18).
- [ ] Комірка календаря того ж дня узгоджена: <80% сіра, 80–105% зелена, >105% amber.

**Вітаміни й мінерали:**
- [ ] Розкриття/згортання easeInOut, шеврон 180°; заголовок «N tracked».
- [ ] Goal-нутрієнт ≥100% → зелений чекмарк; limit-нутрієнт (sodium, sugar, satFat, transFat, cholesterol, caffeine): 90–100% amber-смужка, >100% червона + текст «+X over» (чекмарка НЕМАЄ).
- [ ] Немає даних → «—» без смужки; порожній день → реальні «0 / ціль» зі смужкою 3 pt. Долити продукт з даними → «—» стає сумою.
- [ ] Trans fat (без дефолтної норми) → тільки значення, без «/ ціль» і смужки.

**Записи:**
- [ ] Свайп рядка → Delete 88 pt; тап по відкритому рядку закриває його (не відкриває редактор); лонг-тап → меню Edit/Delete.
- [ ] Будь-яке видалення — тільки через підтвердження («…Цю дію не можна скасувати», назва = знімок із запису). Cancel → рядок лишається відкритим.
- [ ] Вставка/видалення рядків анімовані; видалення останнього → плавний свап на зелений порожній стан, «0 items · 0 kcal».
- [ ] Стрес: швидко видалити 3–4 рядки; видалити з шита і одразу відкрити інший — без крешів.
- [ ] Довга назва (60+ симв.) → лінія обрізається «…», ккал-колонка не з'їдається; badge сканера на місці.
- [ ] Плюрали «N items · X kcal»: 1 / 2 / 5 записів (укр. форми).

**Редагування запису (Edit entry):**
- [ ] Префіл = поточна кількість у поточних юнітах; зберегти → змінюється лише кількість, kcal/макро рахуються з замороженого per-100.
- [ ] Кошик у шиті → підтвердження → видалено, шит закрився.
- [ ] РЕГРЕСІЯ (фікс 2026-08-04): «Save changes» без жодної правки на seeded/US-даних → кількість лишається біт-у-біт тією самою (незайманий кейпад комітить точне початкове значення, без переparse/округлення).
- [ ] Round-trip: натиснути цифру і стерти назад до початкового тексту → зберігається точне початкове значення, не показане округлене (детекція «незайманості» — рядкова, §17).
- [ ] Кількість >9999 в одиниці показу (US: залогати 9999 oz → Units=Metric → Edit): кейпад і жива картка показують обрізане значення, рядок щоденника — реальне; Save без правок зберігає реальне (UI-баг показу — §18).

**Зміна дня** (механізм: `Core/OnDayChange.swift` — NSCalendarDayChanged + активація сцени):
- [ ] Застосунок відкритий через північ (і згорнутий, і на передньому плані) → Today перемикається на новий день, вчорашні записи не «липнуть».
- [ ] Візуальний ресет опівночі очікуваний: кільця анімуються з нуля, скрол угору, розкриті секції згортаються (§17).
- [ ] ⚠️ Північ при відкритому Add food / кейпаді / шиті редагування: флоу знищується разом зі старим днем (`.id(dayKey)`), введене губиться (§18) — зафіксувати фактичну поведінку, без крешів. Якщо CTA встигли натиснути до 00:00 — запис іде у день відкриття шита.
- [ ] 10 разів поспіль згорнути/розгорнути застосунок без зміни дня → без миготінь кілець, стрибків скролу, деградації.
- [ ] Зміна таймзони → записи НЕ переїжджають між днями (dayKey заморожений); не-грегоріанський календар пристрою — те саме.

**Незмінність історії (ключовий інваріант):**
- [ ] Залогати → змінити калорії/назву продукту в Edit → у щоденнику стара назва і старі kcal.
- [ ] Видалити продукт → записи лишаються, редагування кількості «сирітського» запису далі працює.

## 4. Add food (список, пошук, recents)

- [ ] З Today — fullScreenCover; з день-детейлу — card sheet. Back-кнопка = назва дня («9 July»).
- [ ] Recents: до 8 чипів, останній залогований перший, чип показує останню кількість («60 g · 228 kcal»); зникають при введеному пошуку. Тап по чипу однаково відкриває кейпад на 100 г/мл (§17).
- [ ] Пошук: case-insensitive по назві; порожній результат → «No products match “X”». Пошук з одного пробілу: Recents зникають, список повний, «No products match» не показується (§18, дрібне).
- [ ] Сортування: за останнім логуванням/створенням DESC; після логування продукт піднімається вгору.
- [ ] Свайп рядка: Delete + Edit (по 88 pt); алерт видалення продукту каже «Your logged entries stay».
- [ ] Видалити продукт, поки відкритий шит кількості цього ж продукту → лог проходить (знімок уже скопійований), lastQuantity не оновлюється, чип зникає з Recents — без крешів.
- [ ] Банер AdMob під списком — free + після grace.
- [ ] Після успішного логування шит кількості закривається І сторінка Add food закривається — юзер на екрані дня.

## 5. Форма продукту

- [ ] Режими: New (з логування — з тумблером «Save to My products», дефолт ON), «+» біля MY PRODUCTS (без тумблера), Edit.
- [ ] CTA: тумблер ON → «Save» (зберігає БЕЗ логування); OFF → «Add to today» (логує одразу, кількість = введене Per X; продукт у списку НЕ з'являється, запис переживає перезапуск).
- [ ] CTA активна лише коли: назва непорожня + калорії парсяться + Per > 0. «0» калорій — валідний (продукт на 0 kcal створюється; вирішити, чи це ок — §18).
- [ ] Нулі не префіляться — порожні поля з плейсхолдером «0».
- [ ] «На X»: Per = 50, Calories = 100 → у списку «200 kcal / per 100 g». Каптіон слідує за Per («NUTRITION (PER 30 G)»).
- [ ] Ліміти вводу в кожному полі: «12345»→«1234»; «1,2,3»→«1,2»; «,5»→«0,5»; paste «12.3456»→«12.3»; літери ріжуться.
- [ ] ar-локаль: «١٥٠٫٥» НЕ перетворюється в 1505 (регресія роздільника «٫»).
- [ ] Штрихкод: чип «BARCODE SAVED» тільки після скану; ручна форма поля barcode не має; Edit сканованого показує чип.
- [ ] OFF-продукт без нутрієнтів → картка «No nutrition data yet» (показується лише коли ВСІ 4 макро нульові І мікро порожні; продукт з самим натрієм і нульовими макро дає порожню форму без нотиці).
- [ ] РЕГРЕСІЯ (фікс 2026-08-04): Back на брудній формі → «Discard changes?»; без реальних правок (включно з Edit) — закривається мовчки. Свайп-даун брудної форми ЗАБЛОКОВАНО (`interactiveDismissDisabled`), чиста форма свайпом закривається.
- [ ] Мікронутрієнт з явним «0»: рахується в «N added», але НЕ зберігається (значення ≤0 відкидаються) → на Today «—», не 0. Зафіксувати як очікуване чи баг (§18).
- [ ] ⚠️ Edit product: поле «Per» активне і стоїть «100»; змінити Per на 50 і Save → усі значення продукту перемасштабуються (подвояться). Перевірити свідомо (§18).
- [ ] Продукт, збережений «на X» (некруглий per100Factor): Edit показує значення, округлені до 0.1; Save без правок перезаписує точні збережені округленими (§18 — дзеркало фікса кейпада).
- [ ] Секція Vitamins & minerals: згорнута, показує лише трековані, «Track more nutrients» веде в налаштування.

## 6. Кількість (кейпад)

- [ ] Старт завжди 100 канонічних г/мл (не остання кількість). US+г → відкривається «3.5 oz».
- [ ] РЕГРЕСІЯ (фікс 2026-08-04): незайманий кейпад → зберігається РІВНО 100 г (точне канонічне значення, не 99.2 з re-parse). Жива картка при цьому рахує з показаних 3.5 oz (=99.2 г) → допустима розбіжність ~0.8% між карткою і рядком щоденника (§17).
- [ ] Чипи: 50/100/150/200 (метрика) або 1/2/4/8 oz — тап замінює значення.
- [ ] Кейпад: 4 цифри цілої + 1 десяткова, роздільник locale-aware (укр «,», ар «٫»), другий роздільник не вводиться, backspace на останній цифрі → «0», цифра поверх «0» замінює.
- [ ] Жива картка перераховує KCAL/P/F/C на кожне натискання; CTA сіра при 0.
- [ ] Успішний лог: success-хептика, запис = знімок (назва + per-100 + wasScanned), lastQuantity/lastLoggedAt оновлюються тільки для збережених продуктів.

## 7. Сканер + Open Food Facts

**Фази (8):** requestingPermission (до відповіді на промпт камери — порожній темний екран з хедером, §17) / scanning (вьюфайндер, лінія) / searching (спінер + код) / found (мить, одразу форма) / handedOff (локальний хіт — миттєвий порожній екран до відкриття кількості, §17) / notFound («Create manually» + «Scan again») / denied («Open Settings» + «Add manually instead») / offline («Retry» + «Scan again»). Фази перетікають fade 0.2 с; Back працює в будь-якій фазі.

- [ ] ODbL-футер «Data from Open Food Facts» видно у searching/found/notFound (обов'язкова атрибуція); в offline/denied футера немає — свідомо (§17). Довгі мови (de/el/fi) і піднята клавіатура ручного вводу не ламають нижній бар (ScanBottomBar).
- [ ] Розпізнаються тільки EAN-13/EAN-8/UPC-E/Code128; QR — НІ. UPC-E не розгортається в 12-значну форму → на OFF очікувано notFound (§17).
- [ ] Code128 з нецифровим вмістом (логістична етикетка) → без креша; довгий код не ламає верстку чипа.
- [ ] Успіх камерою: хептика + звук 1057, сесія стоп. Debounce 2 с: notFound/offline → «Scan again» → навести ТОЙ САМИЙ код протягом 2 с → тихо ігнорується (виглядає як «не сканує» — це навмисно); через >2 с — спрацьовує.
- [ ] Ручний ввід на симуляторі: без звуку/debounce (навмисно); пробіли трімляться, порожній ввід — disabled; панель відсутня на реальному девайсі (перевірити на TestFlight).
- [ ] UPC-A/EAN-13: продукт, збережений під 12-значною формою, при скані 13-значної (з нулем) дає локальний хіт — БЕЗ мережі, без близнюка → одразу кейпад кількості (чип коду видно лише у префілд-формі з мережі, не на локальному шляху).
- [ ] Denied: перший вхід — системний промпт; відмова → екран з «Open Settings» (не глухий кут). Відомий нюанс: після видачі дозволу в Settings екран лишається denied до перевідкриття сканера (§18).
- [ ] OFF: 404/status≠1/зламаний JSON → notFound (це НЕ помилка); будь-яка транспортна помилка (Airplane Mode, таймаут, 5xx) → offline, «Retry» доводить до результату.
- [ ] User-Agent `CalorieTracker/1.0 (com.prxfitness.calorietracker; contact@utr.ua)` присутній (Charles/Proxyman) — для 13-значного коду з провідним нулем ідуть ДВА запити, перевірити обидва.
- [ ] Basis-детект: напій (л/мл) → форма на ml; сухе → g. Продукт лише з кДж → коректні kcal (÷4.184).
- [ ] Натрій: sodium відсутній → виводиться з salt×0.4; sodium > salt → теж salt×0.4; у форму йде в мг. Нутрієнти зі значенням 0 з OFF відкидаються → у формі «—», не 0 (§17).
- [ ] Дублікати неможливі: повторне збереження того самого коду оновлює існуючий продукт (один рядок), recency не ламається. (Точне порівняння: пара «12-значний + 13-значний» — окремий кейс у §15/iCloud, §18.)
- [ ] OFF-продукт НЕ зберігається автоматично: Back на незайманій префілд-формі закриває мовчки (без Discard) → у списку і щоденнику нічого (навмисно). Повторний скан незбереженого йде в мережу знову і з'їдає ще один скан.

**Скасування пошуку (фікс 2026-08-04 — регресійний блок):**
- [ ] Повільна мережа (Network Link Conditioner) → скан → Back у фазі searching → rewarded НЕ вискакує поверх Add food, Used НЕ збільшився, форма не відкривається.
- [ ] Back під час searching → одразу знову відкрити сканер → чиста фаза scanning, старий код/результат не «доганяє».
- [ ] Back під час searching в Airplane Mode → після перевідкриття не прилітає «No connection» від скасованого запиту.
- [ ] Спам «Retry» в offline → один результат, одна реклама, один тік лічильника.
- [ ] Rewarded на екрані → згорнути застосунок → повернутись → результат скану не загублений, Used не подвоївся.

Лічильник тікає ТІЛЬКИ коли OFF знайшов новий продукт. Локальний хіт / notFound / denied / manual — безкоштовні. Преміум не тікає. Тік відбувається ДО відкриття форми — скинутий (Discard) продукт скан не повертає.

## 17. Відомі особливості (НЕ баги — не репортити)

- OFF-продукт не зберігається автоматично; повторний скан незбереженого йде в мережу знову (ухвалено 2026-08-03).
- Цілі калорій/макро НЕ історичні: зміна цілі перефарбовує минулі дні (заморожений лише набір нутрієнтів і знімки їжі).
- Фаза «Product found» — мить, скріншотом не зловити. Фази requestingPermission і handedOff — короткий порожній темний екран (не креш).
- ODbL-футер сканера відсутній у станах offline/denied (свідомо — даних OFF там не показано).
- UPC-E розпізнається, але не розгортається у 12-значну форму → на OFF очікувано notFound.
- Нутрієнти зі значенням 0 з OFF відкидаються → у формі «—», не 0 («немає даних» ≠ 0).
- Порожній минулий день: жодних кілець/банера — лише сіра картка.
- Підзаголовок з датою на Today — тільки iOS 26+.
- Кількість завжди стартує зі 100 (не з останньої), навіть з Recents-чіпа з іншою кількістю. Незайманий кейпад зберігає рівно 100 канонічних; жива картка рахує з показаного (3.5 oz = 99.2 г) → розбіжність ~0.8% з рядком щоденника. Round-trip тексту до початкового зберігає точне початкове значення.
- Продукт з 0 kcal валідний і логається.
- Логування в минулий день ставить запис останнім у списку (loggedAt = зараз).
- Повернення на таб Calendar завжди відкриває Month + поточний місяць (стан скидається).
- Сьогоднішня комірка календаря має живе кільце в кольорах CalendarRingState (вранці при <80% — сіре) і кільце навіть без записів.
- Остання ніч місяця: після півночі маркер «сьогодні» зникає з видимої сітки (anchor лишається на старому місяці).
- Детейл минулого дня малює кільця «живою» палітрою (зелена при 60%), а комірка сітки — ретроспективною (сіра) — дві різні палітри за дизайном.
- Nutrients-картка календаря порівнює середнє за період з денною нормою.
- Гілки «без цілі калорій» на Today недосяжні (ціль завжди є, дефолт 2000) — не шукати.
- Опівночі Today «перезбирається»: кільця анімуються з нуля, скрол угору, секції згортаються.
- Grace-якір реклами (24 год) сідиться при першому рендері рекламної поверхні, не в момент інсталяції.
- Тік ліміту сканів відбувається до відкриття форми: Discard префілд-форми скан не повертає.
- Роздільники чисел/дні тижня перемикаються на нову мову лише після рестарту.
- Delete all data не повертає онбординг і не скидає мову/review/ads-якорі; isPremium переживає Delete (підписку видалення даних не скасовує).
- Смарт-нагадування живуть у вікні 7 днів від останньої активації — без відкриттів застосунку серія закінчується (лишається re-engagement).
- Виджет-код у `CalorieWidgetSource/` НЕ входить у білд (немає таргета) — з тестплану виключено.
