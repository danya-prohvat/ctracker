# TESTPLAN

## 1. Перший запуск і онбординг

**Кроки онбордингу (7):** стать → вік → зріст/вага → активність → цільова вага → «Calculating…» → «Your plan» → Continue.

- [ ] **Units за регіоном пристрою**
  Кроки: 1) Постав регіон US (§0.9). 2) Чиста інсталяція, пройди онбординг. 3) Settings → Units.
  Очікується: Units = US (oz / fl oz). Повтори з регіоном UK, UA, DE, FR, JP → Metric.

- [ ] **Вибір юзера не перезаписується**
  Кроки: 1) Після попереднього тесту вручну перемкни Units на протилежне. 2) Вбий застосунок, запусти знову.
  Очікується: лишилось те, що вибрав ти, а не дефолт регіону.

- [ ] **Мова = мова пристрою**
  Кроки: чиста інсталяція → Settings → рядок Language.
  Очікується: інтерфейс мовою пристрою; у рядку написано «System», під ним немає футноута.

- [ ] **Перша доба без реклами**
  Кроки: чиста інсталяція (не чіпай Test) → зайди в Settings, Calendar, Add food (FAB «+»).
  Очікується: жодного банера ніде. (Коли саме стартує відлік доби — §16.)

- [ ] **Прогрес і Skip**
  Кроки: проходь кроки онбордингу.
  Очікується: капсула прогресу зверху росте на кожному кроці; на кожному кроці є кнопка Skip; кнопки «Назад» немає (це очікувано, §16). Стать і активність переходять далі самі через ~0.2 с після вибору. Є варіант «Prefer not to say» для статі. Вік — колесо 10–99, дефолт 25.

- [ ] **Тумблер юнітів пише в налаштування одразу**
  Кроки: 1) Дійди до кроку зріст/вага. 2) Перемкни тумблер на ft · lbs. 3) Натискай Skip до кінця, закрий пейвол. 4) Settings → Units.
  Очікується: US.

- [ ] **Перемикання юнітів не «псує» значення**
  Кроки: на кроці зріст/вага постав 175 см / 70 кг → перемкни на ft·lbs → назад на cm·kg.
  Очікується: на колесах приблизно ті самі значення (дрейф ±0.5 кг допустимий). Діапазони коліс: 120–220 см / 35–200 кг; 4′0″–7′0″ / 77–440 lbs.

- [ ] **Skip = дефолтні цілі, Finish = цілі з плану**
  Кроки: (а) чиста інсталяція → усі кроки через Skip → Settings → Goals. (б) чиста інсталяція → заповнити всі кроки → на «Your plan» натиснути Continue → Settings → Goals.
  Очікується: (а) 2000 kcal / 150 P / 67 F / 200 C; (б) числа з екрана «Your plan».

- [ ] ⚠️ **Skip на «Your plan» стирає правки** (відомий баг, §17)
  Кроки: дійти до «Your plan» → відредагувати калорії (напр. 2500) → натиснути Skip → Settings → Goals.
  Очікується зараз: цілі дефолтні (2000), а не 2500. Просто зафіксувати, що поведінка саме така.

- [ ] **Continue без Done на клавіатурі**
  Кроки: на «Your plan» тапнути в поле калорій → ввести 2500 → НЕ натискаючи Done, одразу натиснути Continue → Settings → Goals.
  Очікується: 2500 записалось.

- [ ] **Онбординг стартує в імперії при регіоні US**
  Кроки: регіон US → чиста інсталяція → дійти до кроку зріст/вага.
  Очікується: тумблер уже на ft · lbs.

- [ ] **Пейвол після онбордингу**
  Кроки: закінчити онбординг (Finish або Skip) → дивитись на Today.
  Очікується: ~1 с видно Today → зверху виїжджає пейвол на весь екран. Свайп-даун його НЕ закриває; через 1.5 с з'являється X — він єдиний вихід.

- [ ] **ATT-промпт поверх онбордингу не ламає флоу**
  Кроки: чиста інсталяція → почати онбординг.
  Очікується: через ~0.7 с вилізе системний алерт «Allow … to track…» — можливо поверх першого кроку. Натисни будь-який варіант → онбординг продовжується нормально. Алерт показується лише один раз за життя інсталяції.

- [ ] **Відновлення перерваного онбордингу**
  Кроки: 1) Дійти до кроку активність (4-й) → вбити застосунок (свайп у app switcher) → запустити.
  Очікується: онбординг відкривається на тому ж кроці. Але план далі порахується з дефолтів — раніше введені відповіді загублені (відомий баг, §17).
  2) Дійти до «Calculating…» → вбити застосунок у ці 1.8 с → запустити.
  Очікується: знову «Calculating…» і потім «Your plan».

- [ ] **Холодний старт без блимання**
  Кроки: чиста інсталяція → запустити з іконки (не з Xcode).
  Очікується: одразу перший крок онбордингу, без порожнього білого/сірого кадру перед ним.

## 2. Today і щоденник

Для більшості тестів потрібні дані: «Тестові дані» (§0.1) або створи 2–3 продукти руками (FAB «+» → New product).

### 2.1. Базовий флоу

- [ ] **Створити продукт і залогати**
  Кроки: Today → FAB «+» → New product → назва «Test», Calories 200, Protein 10 → Save → у списку My products тапнути «Test» → у кейпаді лишити 100 → Log.
  Очікується: шит закрився, ти на Today, рядок «Test · 100 g · 200 kcal» у списку, кільце калорій наповнилось, числа «перекрутились» (анімація, не стрибок).

- [ ] **Змінити кількість запису**
  Кроки: тапнути рядок «Test» → у кейпаді ввести 50 → Save changes.
  Очікується: рядок показує 50 g · 100 kcal, кільця та «залишилось» перерахувались.

- [ ] **Видалити запис**
  Кроки: свайп рядка вліво → Delete → підтвердити в алерті.
  Очікується: рядок зник з анімацією, суми зменшились.

### 2.2. Вигляд

- [ ] **Заголовок при скролі**
  Кроки: залогати 5+ записів, щоб було що скролити → скрол униз.
  Очікується: великий заголовок «Today» перетворюється на маленький по центру. Підзаголовок з датою під заголовком є тільки на iOS 26+.

- [ ] **Макет**
  Очікується на Today: велике кільце калорій з підписом «залишилось сьогодні»; під ним три макро-кільця з підписом «з 150 g» (ціль); FAB «+» з градієнтом внизу праворуч; таб-бар видимий.

- [ ] **Анімації**
  Кроки: перейти на таб Calendar → назад на Today.
  Очікується: кільця наповнюються «пружинкою» (з невеликим перельотом). Залогати щось → числа міняються анімацією прокрутки цифр.

- [ ] **Відсотки макро**
  Кроки: (а) у день із записами тапнути по зоні макро-кілець; (б) у порожній день тапнути там само.
  Очікується: (а) під кільцями з'являється рядок «P X% · F Y% · C Z% of calories»; (б) нічого не з'являється.

- [ ] **Net carbs**
  Кроки: Settings → Goals → увімкнути Net carbs → Today.
  Очікується: рядок «Net carbs: X». Залогати продукт, у якого клітковина не заповнена → «—», а не «0». Створити продукт з клітковиною 20 г і вуглеводами 10 г → Net carbs = 0, не мінус.

### 2.3. Кольори кілець (правило: ніколи не червоні)

- [ ] **Норма (<105% цілі)**
  Кроки: залогати так, щоб калорій було менше цілі.
  Очікується: дуга калорій зелена, дуги P/F/C у своїх кольорах; «трек» (незаповнена частина) того самого кольору, але блідий.

- [ ] **Перебір (>105%)**
  Кроки: при цілі 2000 залогати продукт на 3000 kcal.
  Очікується: і дуга, і трек калорій стали жовтогарячими (amber), дуга зупиняється на 100% — другого витка немає. Перебрати тільки білок (створити продукт із 300 г білка) → amber тільки кільце білка, інші свої кольори.

- [ ] **Зона 100–105%**
  Кроки: залогати рівно 2050 kcal при цілі 2000.
  Очікується зараз: число «залишилось» уже червоне (мінус), а кільце ще зелене — задокументована розбіжність (§17).

- [ ] **Узгодженість із календарем**
  Кроки: після кожного з попередніх тестів зайти в Calendar → подивитись комірку сьогодні.
  Очікується: <80% — сіре кільце, 80–105% — зелене, >105% — amber.

### 2.4. Вітаміни й мінерали (секція нижче на Today)

- [ ] **Розкриття**
  Кроки: тапнути заголовок секції.
  Очікується: розкривається плавно, шеврон повертається на 180°. У заголовку «N tracked» (кількість увімкнених нутрієнтів).

- [ ] **Goal vs limit**
  Кроки: 1) Створити продукт з Vitamin C = 200 мг → залогати 100 г. 2) Створити продукт із Sodium = 2500 мг → залогати 100 г.
  Очікується: 1) Vitamin C ≥100% → зелений чекмарк. 2) Sodium: якщо 90–100% норми — смужка amber; >100% — смужка червона + текст «+X over»; чекмарка НЕМАЄ. Limit-нутрієнти: sodium, sugar, saturated fat, trans fat, cholesterol, caffeine.

- [ ] **Немає даних ≠ 0**
  Кроки: (а) залогати продукт БЕЗ жодного мікронутрієнта → розкрити секцію; (б) порожній день (усе видалити) → розкрити; (в) до (а) долити продукт з Vitamin C.
  Очікується: (а) у нутрієнтів «—» без смужки; (б) «0 / ціль» із тонкою порожньою смужкою; (в) «—» у Vitamin C став числом.

- [ ] **Trans fat без норми**
  Кроки: залогати продукт із trans fat = 1 г → розкрити секцію.
  Очікується: тільки значення «1 g», без «/ ціль» і без смужки.

### 2.5. Записи щоденника

- [ ] **Свайп, тап, лонг-тап**
  Кроки: 1) свайп рядка вліво — не до кінця. 2) Тапнути по цьому ж відкритому рядку. 3) Утримати палець на рядку.
  Очікується: 1) з'являється кнопка Delete шириною ~88 pt; 2) рядок закривається, редактор НЕ відкривається; 3) контекст-меню Edit / Delete.

- [ ] **Підтвердження видалення**
  Кроки: Delete будь-яким шляхом (свайп або меню).
  Очікується: алерт з назвою продукту в заголовку і текстом «…Цю дію не можна скасувати». Натиснути Cancel → рядок лишається відкритим (свайпнутим).

- [ ] **Порожній стан**
  Кроки: видалити всі записи дня по одному.
  Очікується: кожне видалення анімоване; після останнього — плавна заміна списку на зелену картку порожнього стану, підпис «0 items · 0 kcal».

- [ ] **Стрес-видалення**
  Кроки: залогати 5 записів → швидко видалити 3–4 підряд (свайп → Delete → підтвердити, без пауз). Потім: відкрити запис → видалити кошиком у шиті → одразу відкрити інший запис.
  Очікується: без крешів і «завислих» рядків.

- [ ] **Довга назва**
  Кроки: створити продукт із назвою на 60+ символів → залогати.
  Очікується: назва обрізана «…» в один рядок, колонка kcal праворуч не з'їхала. Якщо продукт зі скану — іконка сканера в рядку на місці.

- [ ] **Плюрали**
  Кроки: мова uk → залогати 1, потім 2, потім 5 записів.
  Очікується: «1 запис», «2 записи», «5 записів» (правильні форми) + «X ккал».

### 2.6. Редагування запису (тап по рядку)

- [ ] **Префіл і перерахунок із знімка**
  Кроки: 1) Залогати «Test» 100 г (200 kcal). 2) Add food → свайп «Test» → Edit → Calories = 999 → Save. 3) На Today тапнути запис «Test» → у кейпаді 100 → змінити на 200 → Save changes.
  Очікується: кейпад стартував з 100 (поточна кількість); після Save запис показує 200 g · 400 kcal (з старих 200/100 г, а не з нових 999).

- [ ] **Кошик у шиті**
  Кроки: тапнути запис → іконка кошика → підтвердити.
  Очікується: запис видалено, шит закрився.

- [ ] **РЕГРЕСІЯ: Save без правок нічого не змінює** (фікс 2026-08-04)
  Кроки: «Тестові дані» → Settings → Units = US → Today → тапнути будь-який запис → НІЧОГО не натискати → Save changes.
  Очікується: кількість у рядку лишилась абсолютно тією самою (не «округлилась» на 0.1–1%).

- [ ] **Round-trip тексту**
  Кроки: тапнути запис → натиснути одну цифру → стерти її backspace-ом (текст знову початковий) → Save changes.
  Очікується: збережено точне початкове значення (як у попередньому тесті).

- [ ] **Кількість >9999 в одиниці показу** (UI-баг, §17)
  Кроки: Units = US → залогати 9999 oz → Units = Metric → тапнути запис.
  Очікується зараз: у кейпаді і на живій картці значення обрізане до 4 цифр, а в рядку щоденника — реальне (283 кг). Save без правок зберігає реальне.

### 2.7. Зміна дня (як робити «Північ» — §0.8)

- [ ] **Today перемикається на новий день**
  Кроки: (а) Today на екрані → перевести дату на завтра. (б) Згорнути застосунок → перевести дату → розгорнути.
  Очікується: в обох випадках Today показує новий порожній день, вчорашні записи не лишились у списку.

- [ ] **Візуальний ресет опівночі**
  Очікується під час попереднього тесту: кільця анімуються з нуля, скрол стрибає вгору, розкриті секції згортаються. Це очікувано (§16).

- [ ] ⚠️ **Північ при відкритому шиті** (відомий баг, §17)
  Кроки: відкрити Add food (або кейпад, або редагування) → перевести дату на завтра.
  Очікується зараз: шит зникає, введене губиться. Головне — без креша. Якщо натиснути Log до переводу дати — запис лягає у старий день.

- [ ] **Згортання без зміни дня**
  Кроки: 10 разів поспіль згорнути/розгорнути застосунок.
  Очікується: кільця не миготять, скрол не стрибає, нічого не гальмує.

- [ ] **Таймзона і календар не переносять записи**
  Кроки: 1) Залогати запис. 2) Date & Time → Time Zone → вибрати зону на +10 год (щоб «зараз» стало завтра). 3) Повернутись у застосунок.
  Очікується: запис лишився в тому дні, де був. Те саме, якщо змінити Calendar пристрою на Buddhist/Japanese (Settings → General → Language & Region → Calendar).

### 2.8. Незмінність історії (ключовий інваріант)

- [ ] **Редагування продукту не чіпає історію**
  Кроки: 1) Залогати «Test» (200 kcal). 2) Add food → свайп «Test» → Edit → назва «Test2», Calories 500 → Save. 3) Назад на Today.
  Очікується: у щоденнику досі «Test · 200 kcal».

- [ ] **Видалення продукту не чіпає історію**
  Кроки: 1) Залогати «Test». 2) Add food → свайп «Test» → Delete → підтвердити. 3) Today → тапнути запис «Test» → змінити кількість → Save.
  Очікується: запис живий, редагування кількості працює.

## 3. Add food (список, пошук, recents)

Відкривається з Today через FAB «+», або з день-детейлу календаря через «+ Add food to this day».

- [ ] **Стиль подання**
  Кроки: (а) Today → FAB. (б) Calendar → тапнути минулий день → Add food.
  Очікується: (а) відкривається на весь екран; (б) як картка-шит знизу. Кнопка Back підписана назвою дня («9 July»).

- [ ] **Recents**
  Кроки: залогати 3 різні продукти з різною кількістю → знову відкрити Add food.
  Очікується: зверху ряд чипів Recents — останній залогований перший; на чипі видно останню кількість і kcal («60 g · 228 kcal»); максимум 8 чипів. Почати вводити в пошук → чипи зникають. Тапнути чип → відкривається кейпад, але зі 100 г, а не з 60 (§16).

- [ ] **Пошук**
  Кроки: 1) Ввести назву продукту в іншому регістрі («test» для «Test»). 2) Ввести «zzzzz». 3) Стерти все, ввести один пробіл.
  Очікується: 1) знаходить; 2) «No products match "zzzzz"»; 3) Recents зникли, але список повний і «No products match» не показано (дрібний баг, §17).

- [ ] **Сортування**
  Кроки: подивитись порядок → залогати продукт із середини списку → знову відкрити Add food.
  Очікується: список за останнім логуванням/створенням (нові зверху); залогований піднявся на перше місце.

- [ ] **Свайп продукту**
  Кроки: свайп рядка продукту вліво.
  Очікується: дві кнопки — Delete і Edit (по ~88 pt). Delete → алерт із текстом «Your logged entries stay».

- [ ] **Видалення продукту з відкритим кейпадом**
  Кроки: тапнути продукт → відкрився кейпад → потягнути шит кейпада вниз не до кінця, щоб під ним було видно список (або на iPad, де шит не закриває список) → свайпнути цей самий продукт у списку → Delete → підтвердити → повернутись у кейпад → Log.
  Очікується: лог проходить (знімок уже скопійований), запис у щоденнику є, чип зникає з Recents, без крешів. Якщо на iPhone одночасно недосяжно — пропустити з поміткою «не відтворюється на iPhone».

- [ ] **Банер**
  Кроки: Преміум OFF + Реклама ON → Add food → прокрутити під список My products.
  Очікується: банер AdMob.

- [ ] **Закриття після логування**
  Кроки: Add food → продукт → Log.
  Очікується: закрився і кейпад, і Add food — ти одразу на Today (або на день-детейлі, звідки заходив).

## 4. Форма продукту

Три способи відкрити: (1) Add food → картка **New product** (є тумблер «Save to My products»); (2) Add food → «+» біля заголовка MY PRODUCTS (тумблера немає); (3) Add food → свайп продукту вліво → Edit.

- [ ] **Режими і тумблер**
  Кроки: відкрити форму всіма трьома способами.
  Очікується: (1) тумблер «Save to My products», за замовчуванням ON; (2) тумблера немає; (3) Edit — поля префілені.

- [ ] **Save vs Add to today**
  Кроки: (а) New product, тумблер ON → заповнити → CTA. (б) New product, тумблер OFF → Per = 80 → заповнити → CTA. Після (б) вбити і запустити застосунок.
  Очікується: (а) CTA називається «Save», продукт у списку, у щоденнику нічого. (б) CTA «Add to today», запис 80 г одразу в щоденнику, продукту в списку My products НЕМАЄ; після перезапуску запис на місці.

- [ ] **Валідність CTA**
  Кроки: New product → дивитись на CTA: порожня назва; назва є, калорії порожні; назва + калорії, Per = 0; назва + Calories «0», Per 100.
  Очікується: CTA неактивна в перших трьох; активна в четвертому — продукт на 0 kcal створюється (вирішити, чи це ок — §17).

- [ ] **Плейсхолдери**
  Очікується: у новій формі числові поля порожні із сірим «0», а не заповнені нулями.

- [ ] **Per X**
  Кроки: New product → Per = 50, Calories = 100 → Save → подивитись у списку. Під час вводу Per міняти значення й дивитись на заголовок секції.
  Очікується: у списку «200 kcal / per 100 g» (перерахунок на 100). Заголовок секції слідує за Per: «NUTRITION (PER 50 G)».

- [ ] **Ліміти вводу в полі**
  Кроки: у будь-яке числове поле ввести: «12345»; «1,2,3»; «,5»; вставити з буфера «12.3456»; спробувати літери.
  Очікується: «1234»; «1,2»; «0,5»; «12.3»; літери не з'являються.

- [ ] **Арабський роздільник**
  Кроки: Settings → Language → العربية → New product → Calories → ввести «١٥٠٫٥» (150.5 арабськими) → Save → подивитись kcal у списку.
  Очікується: 150.5, а НЕ 1505.

- [ ] **Чип BARCODE SAVED**
  Кроки: (а) New product вручну; (б) форма після скану (§0.5); (в) Edit сканованого продукту.
  Очікується: (а) поля barcode і чипа немає; (б) і (в) чип «BARCODE SAVED».

- [ ] **Продукт без нутрієнтів з OFF**
  Кроки: відсканувати код продукту, у якого в OFF немає жодного макро (пошукати на world.openfoodfacts.org продукт з порожньою таблицею).
  Очікується: картка «No nutrition data yet». Вона показується лише коли ВСІ 4 макро нульові І мікро порожні; продукт з одним натрієм → порожня форма без картки.

- [ ] **РЕГРЕСІЯ: Discard changes** (фікс 2026-08-04)
  Кроки: (а) New product → ввести назву → Back. (б) Edit існуючого → нічого не міняти → Back. (в) New product → ввести назву → свайп-даун. (г) New product → нічого не вводити → свайп-даун.
  Очікується: (а) алерт «Discard changes?»; (б) закривається мовчки; (в) шит НЕ закривається (заблоковано); (г) закривається.

- [ ] **Мікронутрієнт з явним «0»**
  Кроки: New product → у Vitamin C ввести 0 → подивитись лічильник «N added» → Save → залогати → Today → секція вітамінів.
  Очікується зараз: лічильник рахує його як доданий, але на Today у Vitamin C «—» (нулі не зберігаються). Зафіксувати як очікуване чи баг (§17).

- [ ] ⚠️ **Edit product: поле Per перемасштабовує** (відомий баг, §17)
  Кроки: Edit продукту (200 kcal) → поле Per стоїть «100» → змінити на 50 → Save → подивитись у списку.
  Очікується зараз: 400 kcal — усі значення подвоїлись. Зафіксувати свідомо.

- [ ] **Округлення при Edit продукту «на X»**
  Кроки: New product → Per = 30, Calories = 100 → Save (per-100 = 333.33…) → Edit цього продукту.
  Очікується зараз: у формі показано 333.3 (округлено); Save без правок перезапише точне значення округленим (§17 — дзеркало виправленого бага кейпада).

- [ ] **Секція Vitamins & minerals у формі**
  Кроки: New product → прокрутити вниз.
  Очікується: секція згорнута; після розкриття — тільки увімкнені (трековані) нутрієнти; посилання «Track more nutrients» веде в Settings → нутрієнти.

## 5. Кількість (кейпад)

Відкривається тапом по продукту в Add food.

- [ ] **Старт зі 100**
  Кроки: (а) Units = Metric → тапнути продукт. (б) Units = US → тапнути продукт у грамах.
  Очікується: (а) «100 g»; (б) «3.5 oz». Завжди 100 канонічних, навіть якщо минулого разу логав 60.

- [ ] **РЕГРЕСІЯ: незайманий кейпад = рівно 100 г** (фікс 2026-08-04)
  Кроки: Units = US → тапнути продукт → нічого не натискати → Log → Units = Metric → подивитись рядок.
  Очікується: рівно «100 g» (не 99.2). Жива картка в кейпаді при цьому рахувала з 3.5 oz = 99.2 г → різниця ~0.8% між карткою і рядком допустима (§16).

- [ ] **Чипи**
  Очікується: під полем чипи 50 / 100 / 150 / 200 (Metric) або 1 / 2 / 4 / 8 oz (US). Тап по чипу повністю замінює значення.

- [ ] **Клавіші**
  Кроки: 1) Ввести 12345. 2) Ввести 1,2,3 (роздільник двічі). 3) Стерти backspace-ом усе. 4) На «0» натиснути 5.
  Очікується: 1) максимум 4 цифри цілої + 1 десяткова; 2) другий роздільник не вводиться; роздільник — locale-aware (uk «,», ar «٫»); 3) на останній цифрі backspace дає «0»; 4) «5», а не «05».

- [ ] **Жива картка і CTA**
  Кроки: натискати цифри → дивитись картку над кейпадом; ввести 0.
  Очікується: KCAL / P / F / C перераховуються на кожне натискання; при 0 кнопка Log сіра.

- [ ] **Успішний лог**
  Кроки: Log.
  Очікується: коротка success-вібрація (реальний пристрій); у щоденнику запис зі знімком (назва, per-100, ознака «сканований»). Для продукту з тумблером «Save to My products» = OFF (§4) lastQuantity у Recents не оновлюється (продукт не в списку).

## 6. Сканер + Open Food Facts

Відкривається: Add food → картка **Scan**. На симуляторі — ручний ввід коду (§0.5).

**Фази (8):** requestingPermission (поки не відповів на промпт камери — темний порожній екран із хедером, не креш, §16) → scanning (вьюфайндер, лінія) → searching (спінер + код) → found (мить, одразу форма) або handedOff (локальний хіт — мить порожнього екрана до кейпада, §16) або notFound («Create manually» + «Scan again») або offline («Retry» + «Scan again»); окремо denied («Open Settings» + «Add manually instead»). Фази перетікають fade 0.2 с; Back працює в будь-якій.

- [ ] **Базовий скан і збереження**
  Кроки: Scan → ввести `5449000000996` → дочекатись форми → Save.
  Очікується: форма префілена (назва Coca-Cola, kcal, макро, чип BARCODE SAVED); після Save продукт у списку My products.

- [ ] **ODbL-футер**
  Кроки: пройти фази searching / found / notFound (`4444444444448`); потім offline (Airplane Mode) і denied.
  Очікується: у searching/found/notFound унизу «Data from Open Food Facts»; в offline/denied футера немає — свідомо (§16). Додатково: мова de або fi + піднята клавіатура ручного вводу → нижній бар не ламається.

- [ ] **Типи кодів (реальний пристрій)**
  Кроки: навести на QR-код; на UPC-E (8-значний з упаковки US); на Code128 з літерами (логістична етикетка).
  Очікується: QR не розпізнається взагалі; UPC-E зчитується, але на OFF дає notFound (§16); Code128 з літерами — без креша, довгий код не ламає верстку чипа.

- [ ] **Звук, хептика, debounce (реальний пристрій)**
  Кроки: 1) Навести на робочий код. 2) Навести на вигаданий → notFound → «Scan again» → протягом 2 с знову навести на ТОЙ САМИЙ вигаданий код. 3) Почекати >2 с, навести знову.
  Очікується: 1) вібрація + системний «тік», камера зупинилась; 2) нічого не відбувається (виглядає як «не сканує» — навмисно); 3) спрацьовує.

- [ ] **Ручний ввід (симулятор)**
  Кроки: ввести код з пробілами навколо; лишити поле порожнім.
  Очікується: пробіли обрізаються, порожнє поле → кнопка неактивна; звуку і debounce немає (навмисно). На TestFlight поле ручного вводу має бути відсутнє.

- [ ] **UPC-A ↔ EAN-13 локальний хіт**
  Кроки: 1) Ввести будь-який реальний 12-значний UPC-A код (з американської упаковки; або взяти 13-значний EAN, що починається з 0, і відкинути нуль) → Save. 2) Ввести той самий код із провідним нулем (13 цифр).
  Очікується: 2) без мережі, без продукту-близнюка — одразу відкривається кейпад кількості (чип коду видно тільки в префілд-формі з мережі).

- [ ] **Відмова в камері**
  Кроки: чиста інсталяція → Scan → на системному промпті «Don't Allow».
  Очікується: екран denied з кнопкою «Open Settings» (веде в налаштування застосунку) та «Add manually instead». Нюанс: дозволити камеру в Settings і повернутись → екран лишається denied до перевідкриття сканера (§17).

- [ ] **notFound vs offline**
  Кроки: (а) ввести `4444444444448`. (б) Airplane Mode → ввести робочий код → вимкнути Airplane → «Retry».
  Очікується: (а) notFound (це НЕ помилка); (б) спершу offline, після Retry — форма.

- [ ] **User-Agent і два запити** (через проксі, §0.11)
  Кроки: ввести 13-значний код із провідним нулем (напр. `0` + 12-значний).
  Очікується: у запитах до openfoodfacts заголовок `User-Agent: CalorieTracker/1.0 (com.prxfitness.calorietracker; contact@utr.ua)`; запитів два — з 13 і з 12 цифрами.

- [ ] **Детект основи (g/ml) і кДж**
  Кроки: `5449000000996` (напій) і `3017620422003` (сухе). Знайти на OFF продукт лише з kJ.
  Очікується: напій → форма на ml; сухе → g. kJ-продукт → kcal порахувались (÷4.184).

- [ ] **Натрій із солі, нулі з OFF**
  Кроки: знайти продукт, у якого в OFF є salt, але нема sodium (або sodium > salt).
  Очікується: у формі Sodium = salt × 0.4 (у мг). Нутрієнти, які в OFF стоять як 0, у формі порожні («—»), не 0 (§16).

- [ ] **Без дублікатів**
  Кроки: ввести `3017620422003` → Save → у списку свайп цього продукту → Edit → змінити назву → Save → знову Scan → ввести `3017620422003`.
  Очікується: другий скан дає локальний хіт (одразу кейпад, без мережі); у списку ОДИН продукт з цим кодом, і він угорі списку.

- [ ] **OFF-продукт не зберігається сам**
  Кроки: ввести новий код → на префілд-формі нічого не чіпати → Back.
  Очікується: закрилось мовчки (без Discard), у списку і щоденнику нічого. Ввести той самий код знову → знову йде в мережу і знову витрачає безкоштовний скан (навмисно, §16).

### 6.1. Скасування пошуку (фікс 2026-08-04 — регресійний блок; повільна мережа — §0.10)

- [ ] **Back під час searching**
  Кроки: Реклама ON, Used ≥ 1 (щоб реклама показалась би) → повільна мережа → ввести новий код → поки спінер — Back.
  Очікується: ти в Add food; реклама НЕ вискакує; Used у Test не збільшився; форма не відкривається.

- [ ] **Перевідкриття після Back**
  Кроки: попередній тест → одразу знову Scan.
  Очікується: чиста фаза scanning; старий результат не «доганяє».

- [ ] **Back в Airplane Mode**
  Кроки: Airplane Mode → ввести код → під час searching Back → знову Scan.
  Очікується: не прилітає екран offline від скасованого запиту.

- [ ] **Спам Retry**
  Кроки: Airplane Mode → код → offline → вимкнути Airplane → швидко тапнути «Retry» 5 разів.
  Очікується: один результат, одна реклама (якщо гейт), один тік Used.

- [ ] **Згорнути під час реклами**
  Кроки: отримати rewarded → згорнути застосунок → повернутись → закрити рекламу.
  Очікується: форма з результатом відкрилась, Used не подвоївся.

- [ ] **Гонка** (відомий баг, §17)
  Кроки: кілька разів спробувати натиснути Back рівно в момент приходу відповіді.
  Очікується зараз: можлива мовчазна втрата одного скану. Зафіксувати, якщо зловив.

## 7. Ліміт сканів + rewarded-реклама

Правило: лічильник тікає ТІЛЬКИ коли OFF знайшов новий продукт. Локальний хіт / notFound / denied / ручне створення — безкоштовні. Преміум не тікає. Тік відбувається ДО відкриття форми — Discard префілд-форми скан не повертає. Поточний Used — у Test → «Reset free scans».

**Підготовка перед блоком:** Преміум OFF, Реклама ON, Скинути скани. НЕ використовувати `-initialAddRoute scan` (обходить гейт, §0.3). Потрібно кілька різних робочих кодів — знайди 3–4 на world.openfoodfacts.org.

- [ ] **Скан 1**
  Кроки: Scan → новий код.
  Очікується: реклами немає, форма одразу; Used = 1.

- [ ] **Скан 2 — реклама між пошуком і результатом**
  Кроки: Scan → інший новий код.
  Очікується: після спінера з'являється rewarded-реклама; екрана «Product found» не видно, поки рекламу не закрито; після закриття — форма. (Гейт = Used ≥ 1: якщо Преміум ON → OFF при Used = 1, наступний скан одразу з рекламою.)

- [ ] **Реклама не блокує результат**
  Кроки: (а) закрити rewarded достроково (не додивившись). (б) Відкрити сканер і ввести код МИТТЄВО (щоб реклама не встигла завантажитись).
  Очікується: (а) форма однаково відкривається; (б) результат одразу без реклами.

- [ ] **Discard не повертає скан**
  Кроки: після реклами відкрилась форма → Back → Test → подивитись Used.
  Очікується: Used уже +1 (очікувано).

- [ ] **Повторний скан збереженого — безкоштовно**
  Кроки: зберегти продукт зі скану → знову ввести його код → Test → Used.
  Очікується: без реклами, без тіку, одразу кейпад.

- [ ] **Grace-період і лічильник**
  Кроки: Test → «Ads: restart ad-free day» → новий код → Test → Used → «Ads: skip ad-free day» → ще один новий код.
  Очікується: під час grace реклами немає, але Used тікнув; після skip — реклама вже на наступному скані.

- [ ] **Ліміт 10**
  Кроки: довести Used до 10 (10 різних нових кодів; або за потреби скинути й повторити) → Add food → тапнути Scan.
  Очікується: відкривається пейвол, не сканер; логування їжі при цьому працює. Купити преміум на цьому пейволі (§0.6) → Scan одразу працює.

- [ ] **Преміум без ліміту**
  Кроки: Преміум ON → довести Used до 10 не вдасться, тому: спершу на Free довести Used до 10 → Преміум ON → Scan → сканувати 3 нових коди.
  Очікується: сканер відкривається (пейвола немає), реклами немає, Used не росте.

- [ ] **Преміум куплений під час відкритого сканера**
  Кроки: Free, Used ≥ 1 → відкрити сканер → з екрана сканера це неможливо перевірити на iPhone (немає доступу до Settings) → пропустити з поміткою «недосяжно на iPhone»; на iPad зі Slide Over — за бажанням.

## 8. Calendar + 30-денний замок

Підготовка: «Тестові дані» (дають записи глибше 30 днів). Преміум OFF для тестів замка.

- [ ] **Режими Week / Month**
  Кроки: відкрити таб → перемкнути на Week → назад на Month.
  Очікується: дефолт Month; перемикання — fade + плавна зміна висоти. У Week заголовок виду «Jul 6 – 12». ⚠️ Month→Week відкриває тиждень із 1-м числом місяця, а не поточний (§17).

- [ ] **Навігація**
  Кроки: тапати chevron-и; свайпати сітку горизонтально; свайпнути по діагоналі; свайпнути коротко (<40 pt).
  Очікується: сітка їде slide-ом у напрямку кроку; кільця нової сітки наливаються заново; діагональний свайп не «з'їдає» тап по комірці; короткий свайп не гортає.

- [ ] **Комірки**
  Очікується: день з даними — кільце + число; майбутні дні — бліді і не тапаються; якщо в Goals прибрати ціль калорій (неможливо — дефолт 2000, §16) → повне сіре кільце.

- [ ] **Сьогодні**
  Кроки: подивитись комірку сьогодні вранці при <80% і в порожній день.
  Очікується: зелений диск + жирне число + живе кільце: при <80% — СІРЕ (не баг); у порожній день теж є кільце з порожнім треком (§16).

- [ ] **День з 0 ккал**
  Кроки: у минулий день залогати тільки продукт на 0 kcal.
  Очікується: кільце без заповнення, але число НЕ бліде (відрізняється від «немає записів»).

- [ ] **Замок**
  Кроки: Преміум OFF → гортати назад більше ніж на 30 днів; тапнути замкнений день; гортати вперед у майбутнє і назад.

- [ ] **Nutrients card**

## 11. Нотифікації і review-промпт

**Передумова:** Reminders за дефолтом OFF, онбординг дозвіл не питає → на чистій інсталяції нічого не планується, поки не ввімкнеш Reminders. Перевіряти через Test → «Список нотифікацій» (§0.1), а не чекати реального часу.

### 11.1. Смарт-нагадування (2 на день: 14:00 і 20:00, вікно 7 днів)

## 16. Відомі особливості (НЕ баги — не репортити)

- OFF-продукт не зберігається автоматично; повторний скан незбереженого йде в мережу знову (ухвалено 2026-08-03).
- Цілі калорій/макро НЕ історичні: зміна цілі перефарбовує минулі дні (заморожений лише набір нутрієнтів і знімки їжі).
- Фаза «Product found» — мить, скріншотом не зловити. Фази requestingPermission і handedOff — короткий порожній темний екран (не креш).
- ODbL-футер сканера відсутній у станах offline/denied (свідомо — даних OFF там не показано).
- UPC-E розпізнається, але не розгортається у 12-значну форму → на OFF очікувано notFound.
- Нутрієнти зі значенням 0 з OFF відкидаються → у формі «—», не 0 («немає даних» ≠ 0).
- Порожній минулий день: жодних кілець/банера — лише сіра картка.
- Підзаголовок з датою на Today — тільки iOS 26+.
- Кількість завжди стартує зі 100 (не з останньої), навіть з Recents-чіпа з іншою кількістю. Незайманий кейпад зберігає рівно 100 канонічних; жива картка рахує з показаного (3.5 oz = 99.2 г) → розбіжність ~0.8% з рядком щоденника. Round-trip тексту до початкового зберігає точне початкове значення.
- Продукт з 0 kcal валідний і логається.
- Логування в минулий день ставить запис останнім у списку (loggedAt = зараз).
- Повернення на таб Calendar завжди відкриває Month + поточний місяць (стан скидається).
- Сьогоднішня комірка календаря має живе кільце в кольорах CalendarRingState (вранці при <80% — сіре) і кільце навіть без записів.
- Остання ніч місяця: після півночі маркер «сьогодні» зникає з видимої сітки (anchor лишається на старому місяці).
- Детейл минулого дня малює кільця «живою» палітрою (зелена при 60%), а комірка сітки — ретроспективною (сіра) — дві різні палітри за дизайном.
- Nutrients-картка календаря порівнює середнє за період з денною нормою.
- Гілки «без цілі калорій» на Today недосяжні (ціль завжди є, дефолт 2000) — не шукати.
- Опівночі Today «перезбирається»: кільця анімуються з нуля, скрол угору, секції згортаються.
- Grace-якір реклами (24 год) сідиться при першому рендері рекламної поверхні, не в момент інсталяції.
- Тік ліміту сканів відбувається до відкриття форми: Discard префілд-форми скан не повертає.
- Роздільники чисел/дні тижня перемикаються на нову мову лише після рестарту.
- Delete all data не повертає онбординг і не скидає мову/review/ads-якорі; isPremium переживає Delete (підписку видалення даних не скасовує).
- Смарт-нагадування живуть у вікні 7 днів від останньої активації — без відкриттів застосунку серія закінчується (лишається re-engagement).
- Виджет-код у `CalorieWidgetSource/` НЕ входить у білд (немає таргета) — з тестплану виключено.

- ✅ Реклама/списаний скан після закриття сканера під час пошуку → скасування lookup (§6.1; вузька гонка лишилась, див. нижче).

**Середні:**
- DEBUG Premium override злітає при кожній активації сцени (syncEntitlement перезаписує isPremium) — методика перевірки гейтів ненадійна (§0.2, §15).
- Північ знищує відкритий флоу Add food/кейпада/редагування на Today (`.id(dayKey)` міняє identity) — введене губиться без попередження.
- Гонка в сканері: Back рівно в момент приходу OFF-відповіді → реклама може з'явитися поверх Add food + мовчазна втрата скану (вузьке вікно, фікс 08-04 його не закриває).
- CloudKit: близнюки продукту під 12- і 13-значною формою коду переживають dedupeMerged (нормалізації штрихкоду в дедупі немає) — суперечить інваріанту «один barcode = один продукт».
- iCloud: мовчазний фолбек на локальний стор → тумблер ON бреше (синку немає, індикації немає).
- Reminders ON + відкликаний у iOS дозвіл → тиша без жодної індикації; тумблер синкається через CloudKit, а дозвіл — per-device (на другому пристрої ON без дозволу = нічого не приходить).
- Перша відмова в дозволі нотифікацій (notDetermined → Don't Allow) → тумблер досі мовчки відскакує без алерта (алерт лише з другого тапа).
- Restore без покупок — нуль фідбеку; Restore, що знімає преміум, лишає пейвол відкритим мовчки; помилка Restore показує алерт «Purchase failed».
- Сканер лишається в denied після видачі дозволу в iOS Settings (до перевідкриття).
- Calendar: Month → Week → Month може з'їхати на попередній місяць (anchor drift); Month → Week відкриває тиждень 1-го числа, а не поточний.
- Review-тригер «згорає» без показу, якщо застосунок згорнути протягом ~1 с після активації (consume раніше за showRequest).
- Показ кількості >9999 в одиниці показу обрізається до 4 цифр (база права, екран і жива картка брешуть).
- Edit product: активне поле «Per» мовчки перемасштабує всі значення при Save; форма продукту «на X» показує округлені до 0.1 значення і Save без правок перезаписує ними точні (дзеркало виправленого бага кейпада).

**Дрібні:**
- CTA «Add to today» при логуванні в минулий день (текст).
- Порожній стан пушнутого «сьогодні»: текст «Торкніться "+"» без FAB + повний макет з банером і нульовою карткою суми.
- Число залишку червоне вже при >100%, кільце amber лише >105% (узгодити з правилом «без червоного»).
- Подвійна хептика: на клавішах кейпада і на успішному лозі (дві success).
- Language → System не показує футноут рестарту; сам шит пікера мов показує футер «Restart…» завжди (навіть без потреби).
- «Manages via App Store» у Premium-картці — кострубатий копірайт (уже в 35 локалях); uk-алерт нотифікацій змішує «Параметри» і «Налаштування».
- GoalsCalculatorSheet жорстко cm/kg при US units.
- Немає індикації залишку безкоштовних сканів (ліміт з'являється раптово пейволом); `PremiumGate.remainingFreeScans` — мертвий код із застарілим коментом «still counts down».
- ATT-алерт поверх онбордингу.
- Resume онбордингу перераховує план з дефолтів (введені відповіді губляться); Skip на кроці «Your plan» стирає відредагований план.
- Кілька свайп-рядків можуть бути відкриті одночасно; після Cancel рядок лишається відкритим.
- Delete all data скидає unitSystem на дефолт пристрою (не на вибір юзера), повертає 10 сканів (лупхол) і примусово ставить onboardingCompleted=true.
- Пошук з одного пробілу ховає Recents, але показує повний список.
- Зміна цілі калорій не перепланує вечірню нотифікацію до наступної активації; мова вже запланованих нотифікацій — стара до рестарту.
- Мікронутрієнт з явним «0» рахується у «N added», але не зберігається.
- Хінт календаря «Tap a day with a ring…», хоча тап працює і по дню без даних.
- VoiceOver: Back сканера озвучується як «Cancel».
- Застарілі коменти в коді: «3 free scans» і «Local premium override…» (UserSettings), «premium is active» (CalorieTrackerApp), «still counts down» (PremiumGate), «stat-card taps drive it» (CalendarTabView) vs «Cards are read-only» (CalendarStatsRow).
